# Cross-Architecture Reasoning 1.0

Consumes the existing hash-verified read-only Knowledge view and structured
Problem Discovery output. No widget, LLM, second Knowledge database or execution
agent is required. `reason(index, input)` returns the versioned contract in
`schemas/oof-cross-architecture.v1.schema.json`; `validate(output,index)` also
checks live object, representation and relationship identities and provenance.

Multilingual operational cues in `oof-discovery/interpretation.js` propose
candidate architectures and specific verification questions. They are explicitly
non-canonical, not an approved mapping registry or authoritative dependency.
Unknown spaces remain unresolved. Missing formal governed-space metadata stays
null with a labelled source excerpt. No model call fills it in.

Canonical relationships require an existing active authoritative relationship
record, eligible endpoints, and exact source provenance. Shared context alone
produces a hypothesis and an authority limitation. Approved architecture status
does not promote supporting pages. Current SLGA follows the explicit registry
approval; synthetic draft fixtures exercise the in-progress boundary.

The output is report-only. Six architectures, twelve explicit IDs and forty
verified edges bound work. Deterministic analysis uses zero model calls.
