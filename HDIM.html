HDIM — Harm Determination Input Module

OOF® Origin Open Foundation®

Independent Methodological Authority

Canonical Definition

The HDIM — Harm Determination Input Module governs how information
required for formal Harm Determination is identified, admitted, qualified,
structured, associated, differentiated, challenged, limited, updated, and
prepared as a governed Determination Input Set.

HDIM establishes the transition:

Governed Harm Recognition State + Governed Harm Boundary +
Determination-Relevant Information → Input Identification → Input
Qualification → Input Structuring → Governed Harm Determination Input Set

Its central question is:

What information is legitimately fit to enter formal Harm Determination,
and under what qualifications, limitations, uncertainty, and provenance?

  • Operational Role


HDS cannot legitimately determine Harm from an uncontrolled collection of:

reports

observations

records

claims

system outputs

measurements

assumptions

or:

opinions

HDIM establishes the governed input layer before Determination Criteria
are applied.

Its operational role is:

to ensure that Harm Determination begins from an explicit, qualified,
traceable, and appropriately bounded input set rather than from whatever
information happens to be available or convenient.

  • Minimum Implementation Framework


A minimum HDIM implementation requires eight capabilities.

  • Input Identification


Identify materially relevant Recognition, Boundary, subject, temporal,
effect, downstream, operational, evidentiary, historical, supporting, and
contradictory information.

  • Input Qualification


Represent relevance, fitness, scope, provenance, temporal applicability,
subject applicability, uncertainty, confidence, and limitations.

  • Provenance & Transformation Governance


Preserve source, derivation, transformation, aggregation, and dependency
relationships where materially relevant.

  • Composite & Distributed Input Governance


Support inputs distributed across subjects, systems, agents, sessions,
organizations, domains, locations, and time without losing their
collective structure.

  • Conflict, Missing Information & Duplication Governance


Represent contradictory inputs, counterevidence, missing information,
evidence absence, duplicate records, and independent corroboration
distinctly.

  • Input Bias Controls


Prevent preferred outcomes, visibility, authority status, reporting
convenience, organizational interests, or technical availability from
determining the admitted input set.

  • Reassessment & Historical Continuity


Support correction, supersession, invalidation, withdrawal,
requalification, and historical preservation.

  • Governed Output


Produce a traceable Governed Harm Determination Input Set with explicit
readiness status for the next HDS stage.

A system that simply collects available information and passes it directly
into a Harm conclusion does not fully implement HDIM.

  • Use Case 1 — Conflicting Human, Operational, and System
    Information


A subject reports persistent Harm.

An operational record supports part of the reported timeline.

A system record appears to contradict another part.

Additional historical information is incomplete.

HDIM does not decide which conclusion is correct.

It qualifies:

the subject report

the operational record

the contradictory system record

the missing historical information

and:

their respective scope, provenance, uncertainty, and limitations

The resulting Governed Harm Determination Input Set allows HDS to evaluate
the complete basis without silently removing inconvenient information.

The governing principle is:

Contradiction must be governed before it can be evaluated.

  • Governance Logic


HDIM applies the following logic:

Has HRS produced a governed Recognition state and HBS established the Harm
Boundary?

If no:

→ formal Determination Input governance is not ready.

If yes:

→ identify Determination-relevant information.

Is the information relevant to the bounded Harm?

If no:

→ exclude it from the Determination Input Set while preserving the reason
where material.

If yes:

→ assess fitness.

Is the input fit for its intended Determination use?

If yes:

→ qualify it.

If partly:

→ qualify it with limitations.

If unresolved:

→ maintain Pending Qualification.

Does the input conflict with other information?

→ preserve the conflict.

Is the information duplicated?

→ distinguish duplication from independent corroboration.

Is provenance or transformation materially relevant?

→ preserve it.

Is information missing?

→ identify the missing state without converting absence into negative
evidence.

Are several individually incomplete inputs collectively relevant?

→ preserve their composite relationship.

Does the available input set sufficiently support criteria application?

If yes:

→ establish Ready or Ready with Limitations.

If no:

→ establish Not Ready or Conditional Readiness.

  • Canonical Boundary


The HDIM — Harm Determination Input Module governs the identification,
admission, qualification, structuring, provenance, transformation, scope,
fitness, uncertainty, limitations, conflict, contradiction, missing
information, duplication, corroboration, composite relationships,
distributed information, reassessment, and historical continuity of
information used for formal Harm Determination. It produces the Governed
Harm Determination Input Set but does not establish Determination
Criteria, evaluate whether the criteria are satisfied, determine the Harm
Determination State, create the final Governed Harm Record, establish
general causation, assign accountability or liability, or replace
evidence, validation, integrity, identity, operational reality, AI
behavior, autonomous execution, simulation, Value, prediction, or
jurisdiction-specific governance.

  • Canonical Closing Statement


Harm Determination is only as legitimate as the governed basis from which
it begins.

Information must not become evidence merely because it is available,
become reliable merely because it is authoritative, or disappear merely
because it contradicts the expected conclusion.

HDIM ensures that Determination begins with a qualified representation of
what is known, what is uncertain, what conflicts, what is missing, and
where each material input came from.

Before Harm can be determined, the information used to determine it must
itself become governable.
