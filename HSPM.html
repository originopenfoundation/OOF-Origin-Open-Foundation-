HSPM — Harm State Transition Module

OOF® Origin Open Foundation®

Independent Methodological Authority

Canonical Definition

The HSPM — Harm State Transition Module governs how a governed Harm moves
from one canonical Harm State to another when materially sufficient
information establishes that the previous State no longer accurately
represents the Harm's current condition.

HSPM governs transition eligibility, transition basis, direction, timing,
qualification, regression, recurrence, multi-dimensional transition,
transition uncertainty, correction boundaries, and historical continuity
while preserving the identity of the governed Harm across legitimate State
change.

It establishes the transition:

Governed Harm State Persistence + Material State Change → Transition Basis
→ Transition Eligibility → State-to-State Transition → Transition
Qualification → Governed Harm State Transition

Its central question is:

When has a governed Harm changed sufficiently that its current Harm State
must transition to another State, and what transition has legitimately
occurred?

  • Operational Role


HSCM determines:

what State the Harm is in.

HSTM determines:

whether that State continues to apply.

HSPM governs the moment when:

the existing State no longer applies and another State legitimately
begins.

Its operational role is:

to convert material Harm change into an explicit, traceable State
transition without creating a new Harm identity merely because the Harm
condition changed.

  • Position Within HSS


The HSS governance flow is:

State Identification → State Classification → State Persistence → State
Transition → State Monitoring

The Core Module sequence is:

HSIM → HSCM → HSTM → HSPM → HSVM

HSPM receives:

Governed Harm State Persistence

together with materially relevant change information.

It produces:

Governed Harm State Transition

for continued HSS governance.

  • Governed Object


The primary governed object is:

Harm State Transition

A transition connects:

Prior Harm State → Current Harm State

while preserving:

Governed Harm Identity

Therefore:

State Transition ≠ New Harm Object by Default

  • Foundational Transition Principle


The foundational rule is:

A Harm State must change when the Harm materially changes, but the
identity of the Harm must not change merely because its State does.

Conceptually:

Harm₁ / State A → Material Change → Harm₁ / State B

The Harm remains:

Harm₁

unless separate governance establishes otherwise.

  • Transition Eligibility


A State transition becomes eligible when the governed basis establishes
that:

the current State no longer adequately represents the Harm

and:

another canonical State more accurately represents the current condition.

A transition must not be created merely because:

time passed

a new report arrived

an intervention occurred

a system changed

or:

an administrator changed a label

  • Transition Basis


A legitimate transition may be supported by materially relevant changes
in:

Harm manifestation

intensity

persistence

affected scope

functional consequence

subject condition

effect condition

recovery condition

or:

other governed Harm characteristics

The basis must concern the Harm itself.

  • State Signal ≠ State Transition


A State Signal may indicate possible change.

But:

State Signal ≠ State Transition

For example:

new complaint

sensor alert

subject report

system event

new measurement

or:

intervention result

may trigger reassessment without independently establishing a new State.

  • Transition Threshold


Not every fluctuation requires State transition.

HSPM must distinguish:

normal variation within a State

from:

material change requiring another State

Canonical principle:

Variation Within State ≠ State Transition

This prevents excessive state switching caused by insignificant
fluctuations.

  • Transition Timing


HSPM should establish when the transition became applicable where
supportable.

This may differ from:

observation time

reporting time

processing time

or:

record update time

Therefore:

Transition Time ≠ Transition Recording Time by Default

  • Transition Direction


Harm State transitions are not inherently one-directional.

Possible transitions include:

Emerging → Active

Active → Escalating

Escalating → Stabilized

Stabilized → Reduced

Reduced → Recovering

Recovering → Residual

Residual → Resolved

But HAGA™ must also support:

Stabilized → Escalating

Reduced → Active

Recovering → Active

Recovering → Escalating

Residual → Active

and other materially legitimate transitions.

Canonical principle:

Harm reality is not required to follow a linear recovery path.

  • Escalation Transition


A transition to:

Escalating

requires materially supportable worsening of the Harm.

However:

Escalation ≠ Propagation

A Harm may worsen inside its existing governed Boundary without
propagating.

Where Harm spreads, accumulates, compounds, or cascades, HCPS governs
those dynamics.

  • Stabilization Transition


A transition to:

Stabilized

requires sufficient basis that material worsening or improvement has
ceased over the relevant period.

It does not establish:

Recovery

Resolution

or:

Finality

Therefore:

Transition to Stabilized ≠ Harm Resolution

  • Reduction Transition


A transition to:

Reduced

requires actual material decrease in the governed Harm condition.

It cannot be established solely from:

Mitigation Action Completed

Containment Applied

System Fixed

or:

Treatment Started

Canonical principle:

Action Completion ≠ Harm Reduction

  • Recovery Transition


A transition to:

Recovering

requires materially supportable recovery of the affected Harm condition.

Therefore:

Recovery Intervention ≠ Recovering State

The Harm itself must support the transition.

Detailed Recovery governance belongs to HRRHS.

  • Residual Transition


A transition to:

Residual

represents Harm remaining after material recovery, restoration, reduction,
or cessation of the original harmful process.

Residual Harm remains Harm.

Therefore:

Residual ≠ Resolved

and:

Residual ≠ Historical Harm Only

  • Resolution Transition


A transition to:

Resolved

must occur only where applicable Resolution conditions have been
legitimately established through HAGA™ governance.

It must not be inferred from:

system repair

claim closure

payment

lack of complaint

temporary absence of manifestation

or:

end of monitoring

And:

Resolved ≠ Finality

  • Regression


A Harm may transition into an apparently improved State and later worsen.

For example:

Active → Reduced → Active

or:

Recovering → Escalating

HSPM governs such movement as:

State Regression

where the Harm identity remains continuous.

Canonical principle:

Improvement Does Not Make Regression a New Harm by Default.

  • Recurrence


A harmful condition may recur after a period of reduced or absent
manifestation.

HSPM must distinguish:

State recurrence of the same Harm

from:

emergence of a separate Harm

This distinction may require reference to:

Harm identity

Boundary

temporal continuity

effect continuity

subject continuity

and:

relationship to the original Harm

  • Reopening After Resolution


Where materially new information indicates that a Harm previously
represented as Resolved is again materially present, governance must
determine whether this represents:

reopening of the same Harm lifecycle

or:

a new Harm object

HSPM must not automatically assume either.

Canonical principle:

Post-Resolution Harm Manifestation Requires Identity Governance Before
State Assignment.

Finality remains governed by HRFS.

  • Multi-Dimensional Transition


Different Harm dimensions may transition differently.

For example:

Physical: Active → Reduced

Financial: Active → Active

Organizational: Escalating → Stabilized

HSPM must preserve material dimensional differences.

Therefore:

One Dimension Transition ≠ Whole-Harm Transition by Default

  • Subject-Level Transition


Different affected subjects may move through different State transitions.

For example:

Subject A: Active → Recovering

Subject B: Active → Stabilized

Subject C: Active → Escalating

HSPM must preserve these differences where materially relevant.

  • Collective and Composite Transition


A collective or composite Harm must not transition merely because a subset
of its components improved.

Therefore:

Local Transition ≠ Collective Transition

and:

Component Recovery ≠ Composite Recovery

The transition must be evaluated at the level of the governed Harm object.

  • Distributed Transition


Where Harm spans multiple:

systems

agents

organizations

locations

or:

domains

a State transition may depend on distributed information.

Technical fragmentation must not create contradictory independent State
transitions for what remains one materially coherent Harm.

Canonical principle:

Execution or observation boundaries must not redefine Harm transition
boundaries.

  • Mechanism Transition ≠ Harm Transition


The producing mechanism may transition from:

Active → Stopped

Unsafe → Corrected

Deployed → Removed

or:

Model A → Model B

without the Harm transitioning at all.

Therefore:

Mechanism Transition ≠ Harm State Transition

  • Intervention Transition ≠ Harm Transition


Similarly:

Containment Started

Mitigation Completed

Treatment Initiated

Compensation Paid

or:

Recovery Program Closed

are not Harm State transitions by themselves.

The actual Harm condition must change.

  • Transition vs Classification Correction


HSPM must distinguish: State Transition

The Harm condition actually changed.

from: Classification Correction

The Harm condition did not change, but the previous State classification
was incorrect.

Example:

Actual Harm:

Active → Active

Recorded classification:

Stabilized → corrected to Active

This is not:

Stabilized → Active

as a Harm transition.

Canonical distinction:

Representation Change ≠ Reality Change

  • Delayed Recognition of Transition


A State transition may occur before governance recognizes it.

For example:

actual transition — Day 1

observation — Day 3

formal recognition — Day 5

HSPM should preserve the best-governed transition time separately from the
time the transition was recorded.

Therefore:

Late Transition Recognition ≠ Late Transition

  • Transition Uncertainty


Where a transition is materially likely but not sufficiently established,
HSPM should preserve uncertainty.

It must not create a false transition merely because systems require a
single State value.

Possible governance representation may include:

Transition Under Review

Transition Time Uncertain

Destination State Uncertain

or:

Additional Basis Required

  • Transition Confidence


Where useful, HSPM may represent confidence in:

whether transition occurred

when it occurred

or:

which destination State applies

But:

Transition Confidence ≠ Harm Severity

and:

Low Confidence ≠ No Transition

  • Transition History


Every material State transition should preserve:

Harm identity

prior State

destination State

transition basis

transition time

material qualifications

uncertainty

and:

recording time

This creates a traceable:

Harm State Trajectory

  • Transition Chain


Over time, a Harm may produce a chain such as:

Active → Escalating → Stabilized → Reduced → Recovering → Residual

or:

Active → Reduced → Recovering → Active → Escalating

HSPM must preserve the actual trajectory rather than rewrite it into an
idealized linear lifecycle.

Canonical principle:

The governed Harm trajectory must represent what happened, not what was
expected to happen.

  • Transition and HCPS Boundary


A key architectural boundary is:

HSPM governs State-to-State movement.

HCPS governs the Harm dynamics producing material change, accumulation,
compounding, propagation, and cascading.

For example:

HCPS may determine:

Harm propagated to additional systems.

HSPM may determine:

the resulting Harm State changed from Active to Escalating.

Therefore:

Change Mechanism ≠ State Transition

  • Transition and Downstream HAGA™ Processes


Containment, Mitigation, Recovery, and Resolution processes may produce
Harm changes that result in State transitions.

But the governance remains separate:

HCOS → Containment

HMS → Mitigation

HRRHS → Recovery / Residual Harm

HRFS → Resolution / Finality

HSPM → resulting Harm State Transition

This prevents process completion from being mistaken for consequence
change.

Active → Reduced

The Harm remains:

Active

until the actual governed Harm condition supports another State.

The governing principle is:

Process completion does not constitute Harm State transition unless the
Harm itself materially changes.

  • Governance Logic


HSPM applies the following logic:

Does a governed current Harm State exist?

If no:

→ State Transition cannot be formally governed.

If yes:

→ evaluate whether the current State continues to represent the Harm.

Has a material State Signal appeared?

If no:

→ preserve current State subject to Persistence and Monitoring governance.

If yes:

→ evaluate whether material Harm change occurred.

Is the observed difference ordinary variation within the current State?

If yes:

→ no transition.

Has the Harm materially changed?

If no:

→ preserve current State.

If yes:

→ determine the legitimate destination State.

Did the Harm worsen?

→ consider Escalating or another applicable State.

Did it stabilize?

→ consider Stabilized.

Did it materially decrease?

→ consider Reduced.

Is actual Recovery underway?

→ consider Recovering.

Does Harm remain following Recovery?

→ consider Residual.

Have governed Resolution conditions been established?

→ represent Resolved, subject to HRFS.

Then test:

Is this actual Harm change or merely a correction to the previous
classification?

If correction:

→ route to Classification Correction rather than create false transition
history.

Does the apparent transition concern only the producing mechanism or
intervention?

If yes:

→ do not treat it as Harm State transition.

Does the change represent propagation, accumulation, compounding, or
cascading?

→ invoke HCPS for the relevant dynamics.

Does the condition represent the same Harm or potentially a new Harm
object?

If uncertain:

→ return to appropriate identity, Boundary, or Emergence governance.

Then produce:

Governed Harm State Transition

  • Canonical Boundary


The HSPM — Harm State Transition Module governs the eligibility, basis,
threshold, timing, direction, qualification, regression, recurrence,
uncertainty, confidence, historical continuity, and State-to-State
representation of material changes in an already governed Harm State while
preserving Harm identity across legitimate transitions. It does not
initially identify or classify Harm State, govern State Persistence or
systematic Monitoring, determine whether Harm originally exists, redefine
the Governed Harm Boundary, govern the mechanisms through which Harm
accumulates, compounds, propagates or cascades, perform Containment or
Mitigation, govern Recovery or Residual Harm determination, establish
Resolution criteria or Finality, determine general causation, assign
accountability or liability, govern claims or compensation, or replace
operational reality, evidence, validation, integrity, identity, AI
behavior, autonomous execution, simulation, prediction, Value, tax-event,
or jurisdiction-specific governance.

  • Canonical Closing Statement


Harm does not move through a lifecycle because a process says it should.
It moves when the Harm itself materially changes.

A completed intervention does not guarantee improvement, a period of
improvement does not prevent regression, and a change in State does not
automatically create a new Harm.

HSPM preserves the difference between changing reality and changing
labels.

The Harm State changes only when the governed Harm changes enough to
require it.
