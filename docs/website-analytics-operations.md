# Website analytics operations

## Release state

The website collector is disabled by default. The static website is hosted on GitHub Pages; it cannot execute the LaRA Node server. The existing Render reference configuration uses a free service and does not establish persistent storage, and the owner has no access to that service. A separate Supabase Edge Functions implementation and first-party Cloudflare proxy are under development; neither has been deployed or verified. Do not enable the collector or claim production readiness until durable storage, retention, an authenticated admin access path, privacy review, rate limiting, monitoring, backups, and production end-to-end checks have been completed.

Umami was evaluated but its documented default session identifier combines IP address, User-Agent and a rotating salt. That default is incompatible with the task's strict no-fingerprinting requirement. This limited aggregate collector is not presented as feature-equivalent to Umami: it does not estimate visitors, reconstruct journeys, identify bots, or accept raw search queries.

## Configuration

The separate Supabase implementation uses `OOF_ANALYTICS_DATABASE_PASSWORD` for the restricted role, `OOF_ANALYTICS_ADMIN_USER_ID` for the approved administrator, and `OOF_ANALYTICS_PROXY_TOKEN` shared only between the proxy and collector. `OOF_ANALYTICS_ENABLED` remains unset until deployment, retention, backups and protections are verified. Secrets must never be put into the repository or browser. The default Supabase Auth site URL was observed as `http://localhost:3000`; the invitation must not be opened until the correct HTTPS callback is deployed and the redirect is configured and verified. Free Cloudflare Zero Trust checkout requested payment details and authorization for possible overages, so it was not activated.

1. Provision an independently controlled, durable backend outside the public website tree. The GitHub Pages site must have an explicitly configured same-origin reverse proxy for `/_oof/analytics/event`. A free Render filesystem alone is not durable.
2. Provision the Supabase restricted role password in Edge Function secrets and test its TLS connection to the dedicated analytics schema. The functions check the role, row-level security, table permissions and public schema access before use. Do not use the project's privileged default database credential. A temporary authenticated connection probe returned success and was removed. The scheduled `oof-analytics-retention` job runs as the restricted writer, removes records older than 90 days and is scheduled daily at 03:17 UTC; a test execution succeeded with no rows to delete. A verified backup mechanism remains a release blocker.
3. Authenticate the standalone administrator through Supabase Auth and restrict server-side reports to the explicitly approved user ID. Verify invitation redirects, authentication, token handling, MFA policy and denied access before deployment. The existing LaRA administration is unrelated and must not be opened to the public or weakened.
4. Cloudflare Web Analytics is optional. Configure `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_WEB_ANALYTICS_SITE_TAG`, and `CLOUDFLARE_ANALYTICS_API_TOKEN` in the backend environment, not in Git or browser code. GitHub Actions secrets do not automatically become Render environment variables. Use a read-only token with the minimum required permissions.
5. After the prerequisites, privacy notice review, and access controls are verified, change `assets/data/oof-analytics-config.json` to enable collection. The client accepts only the same-origin path `/_oof/analytics/event` and sends requests without cookies or a referrer header. The existing Cloudflare beacon is separate.

## Data and retention

The collector accepts event, content category, coarse referrer category, language, and an optional public canonical content ID from the generated allowlist. It stores daily aggregate counters only; it does not store URLs, IP addresses, user agents, cookies, browser IDs, search terms, LaRA conversations, or visitor-level records. Server infrastructure and network providers may still process request metadata under their own policies. This implementation cannot establish unique visitors, session paths, human identity, or bot classification. Regenerate the allowlist with `node tools/build_website_analytics_catalog.cjs` after changes to the canonical public knowledge registry.

The optional Cloudflare adapter queries only the existing Web Analytics visit grouping by date and country. It does not currently provide HTTP requests, bandwidth, verified bots, or security events; those metrics are shown as unavailable. Cloudflare visits and independent page views are different measures and must not be added together or interpreted as verified humans.

The database prunes old aggregate rows on startup and approximately daily. Arrange restricted, consistent backups and test restores before activation. Supabase's free plan has limitations, including possible inactivity pauses and restrictions on downloadable automatic backups; verify the current service terms and arrange separate backups. For SQLite, use a consistent SQLite backup mechanism. To remove analytics data, disable collection first, then remove the analytics records and all retained backups using the host's authorized procedures; SQLite installations must also account for WAL/SHM companions. Deletion does not remove Cloudflare data.

## Verification

Run `node --test tests/lara/website-analytics.test.js tests/lara/website-analytics-http.test.js tests/lara/website-tracker.test.js` and `node --test tests/lara/*.test.js`. These tests do not prove production persistence, remote authorization, Cloudflare API permissions, legal compliance, or real-browser behavior. Verify those separately before activation. The Cloudflare API adapter must be checked with actual scoped credentials without printing tokens or private analytics into public logs.
