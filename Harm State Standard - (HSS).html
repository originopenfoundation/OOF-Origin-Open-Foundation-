  • Canonical Definition


The Harm State Standard (HSS) governs how a formally governed Harm object
is represented, classified, qualified, monitored, reassessed, and
transitioned according to its current Harm condition throughout the period
between formal Harm Determination and subsequent Harm Change, Propagation,
Containment, Mitigation, Recovery, Residual Harm, Resolution, and
Finality.

HSS establishes the authoritative methodological representation of what
state the governed Harm is currently in, while preserving its identity and
history across changes in intensity, persistence, visibility,
manifestation, affected scope, and operational condition.

It governs the transition:

Governed Harm Record → Harm State Identification → Harm State
Classification → Harm State Persistence → Harm State Transition → Harm
State Monitoring

  • Operational Role


HDS answers:

Can Harm legitimately be determined to exist, and what governed Harm has
been established?

HSS answers the next question:

What is the current governed state of that Harm?

Its operational role is:

to maintain an explicit, current, historically continuous representation
of Harm after Determination so that changes in Harm are governed as state
transitions rather than mistaken for new Harm, disappearance of Harm,
recovery, or finality without sufficient basis.

  • Core Question


What is the current governed state of Harm?

  • Position Within HAGA™


Harm Context → Harm Exposure → Harm Emergence → Harm Recognition → Harm

Harm Containment → Harm Mitigation → Harm Recovery & Residual Harm → Harm
Resolution & Finality

HSS receives the:

Governed Harm Record

from HDS.

It produces a:

Governed Harm State

capable of entering Harm Change & Propagation governance.

  • Governance Flow


The HSS governance flow is:

State Identification → State Classification → State Persistence → State
Transition → State Monitoring

This flow ensures that Harm is not treated as a static binary object after
Determination.

  • Governed Space


HSS governs:

current Harm condition

Harm State identification

Harm State classification

state persistence

state duration

state transition

state uncertainty

state confidence

state monitoring

state reassessment

state correction

state history

and:

state continuity

It does not govern whether Harm originally existed. That function belongs
to HDS.

  • Foundational State Principle


The foundational distinction is:

Harm Determination ≠ Harm State

Determination establishes the governed Harm object.

Harm State describes the current condition of that object.

A Harm may remain the same Harm while its state changes substantially.

  • Canonical Harm States


HSS recognizes the following canonical Harm lifecycle states:

Emerging

Active

Escalating

Stabilized

Reduced

Recovering

Residual

Resolved

These states represent materially different Harm conditions and must not
be collapsed into a simple:

Harm / No Harm

model.

  • Emerging State


Emerging represents governed Harm whose harmful condition has begun to
exist but whose manifestation, extent, stability, or development remains
materially in formation.

Within HSS, Emerging does not redo the HEMS Harm Emergence determination.

It represents the current state of an already governed Harm whose
development remains emergent.

Therefore:

Emergence Governance ≠ Emerging Harm State

  • Active State


Active represents Harm that is currently existing and materially operative
within its governed boundary.

Active Harm may be:

stable

intermittent

continuous

visible

latent in some dimensions

or:

changing

Active does not imply escalation.

  • Escalating State


Escalating represents Harm whose governed condition is materially
worsening.

Escalation may involve:

increasing intensity

increasing effect

increasing persistence

expanding affected scope

or another materially worsening characteristic of the existing Harm.

However, HSS must preserve the boundary with HCPS:

Harm Escalation ≠ Harm Propagation

A Harm may intensify without spreading.

  • Stabilized State


Stabilized represents Harm whose material condition is no longer
significantly worsening or improving within the relevant observation
period.

Stabilization does not establish:

Mitigation

Recovery

Resolution

or:

Finality

Canonical distinction:

Stable Harm ≠ Resolved Harm

  • Reduced State


Reduced represents Harm whose materially governed condition has decreased
relative to an earlier Harm State.

Reduction may result from:

intervention

natural change

environmental change

system change

or other mechanisms.

HSS records the state.

It does not automatically determine why the reduction occurred.

  • Recovering State


Recovering represents Harm for which restoration or recovery is materially
underway but has not yet reached a stable recovered or Residual Harm
condition.

The detailed governance of Recovery belongs to HRRHS.

HSS represents the resulting lifecycle state.

Therefore:

Recovering State ≠ Recovery Governance

  • Residual State


Residual represents Harm that continues to exist after material recovery,
mitigation, restoration, or cessation of the original Harm-producing
mechanism.

Residual Harm may be:

persistent

reduced

irreversible

latent

intermittent

or:

long-term

Canonical principle:

Recovery does not necessarily eliminate Harm.

  • Resolved State


Resolved represents Harm that has satisfied the applicable governed
conditions for Harm Resolution.

However:

Resolved ≠ Final

HRFS determines whether the complete Harm lifecycle has reached legitimate
Finality.

Therefore:

Harm Resolution ≠ Harm Finality

  • State Identification


HSS must establish which Harm object is being state-governed.

State identification must preserve continuity with the:

Governed Harm Record

A Harm State must not become detached from the Harm object to which it
belongs.

Canonical principle:

A state without a governed Harm identity is not a governed Harm State.

  • State Classification


State classification determines which current Harm State best represents
the governed condition.

Classification must use materially relevant information about the Harm
rather than labels selected for administrative convenience.

Where the basis does not support precise classification, uncertainty must
remain visible.

  • State Classification ≠ Harm Redetermination


HSS must not repeatedly re-establish whether the Harm existed merely
because its state changes.

Therefore:

State Change ≠ New Harm Determination by Default

Where the underlying Harm identity remains continuous, HSS governs the
change as a state transition.

  • Harm Identity Across State Change


Conceptually:

Harm₁ / Active → Harm₁ / Escalating → Harm₁ / Stabilized → Harm₁ / Reduced

The state changes.

The Harm identity remains:

Harm₁

unless governance establishes that a separate Harm object has emerged.

  • State Persistence


A Harm State may persist across time.

Persistence governance must preserve:

state start

state duration

continued applicability

material observations

and:

state end or transition

where supportable.

A lack of new observations must not automatically terminate the state.

  • Observation Gap ≠ Harm State End


Canonical principle:

Absence of current observation does not automatically establish absence of
current Harm.

A monitoring gap, reporting gap, system outage, missing measurement, or
lack of complaint must not silently produce:

Resolved

  • Visibility ≠ Harm State


A Harm may become less visible without becoming less real.

Therefore:

Reduced Visibility ≠ Reduced Harm

and:

No Visible Effect ≠ Resolved Harm by Default

This is particularly important for delayed, latent, cognitive, digital,
environmental, and long-duration Harm.

  • State Duration


HSS may govern how long a Harm remains within a particular state.

Duration may be:

known

bounded

estimated

ongoing

or:

uncertain

State duration must not be manufactured beyond the available governed
basis.

  • State Transition


A Harm State changes when materially sufficient conditions establish that
the previous state no longer accurately represents the current Harm
condition.

Conceptually:

State₁ → Material Change → State₂

Transitions must be explicit and historically traceable.

  • State Transition ≠ New Harm


Canonical principle:

Harm State Transition ≠ New Harm Object by Default

A worsening, reduction, stabilization, or recovery of the same Harm should
remain linked to the same Harm identity.

  • State Transition ≠ Determination Reversal


An Established Harm becoming Reduced or Resolved does not mean the
original Harm Determination was wrong.

Therefore:

Harm Improvement ≠ Prior Harm Non-Existence

  • Non-Linear State Transitions


Harm does not necessarily move through states in one direction.

Possible transitions include:

Active → Escalating

Escalating → Stabilized

Stabilized → Escalating

Reduced → Active

Recovering → Residual

Recovering → Escalating

Residual → Active

Resolved → Reopened governance where applicable

HSS must therefore support non-linear Harm trajectories.

  • State Regression


A Harm may deteriorate after improvement.

Therefore:

Improvement ≠ Irreversible Progress

A Reduced or Recovering Harm may return to Active or Escalating where the
governed condition materially worsens.

  • State Recurrence


A harmful condition may recur.

HSS must distinguish:

recurrence of the same Harm

from:

emergence of a new Harm

The distinction depends on Harm identity, Boundary, continuity, temporal
structure, effects, and materially relevant relationships.

  • Intermittent Harm


Some Harm alternates between observable and less observable or inactive
manifestations.

HSS must support:

intermittent state patterns

without forcing each manifestation into a separate Harm object.

Canonical principle:

Intermittent Manifestation ≠ Repeated New Harm by Default

  • Multi-Dimensional Harm State


A Harm may have different state characteristics across dimensions.

For example:

physical effect — Reduced

financial consequence — Active

digital consequence — Stabilized

A single label may therefore be insufficient for complex Harm.

HSS should permit a primary Harm State with material dimensional
qualifications where required.

  • Subject-Level State Differences


Different affected subjects may experience different Harm States within
the same governed Harm object.

For example:

Subject A — Recovering

Subject B — Active

Subject C — Residual

The architecture must preserve those differences without automatically
fragmenting the Harm identity.

  • Collective Harm State


Collective Harm may have a state that cannot be represented simply by
averaging individual subject states.

Therefore:

Collective Harm State ≠ Arithmetic Average of Individual Harm States

Group, organizational, infrastructure, environmental, or societal Harm may
require state representation at the collective level.

  • Composite Harm State


Where Harm exists as a composite condition, HSS must govern the state of
the complete Harm structure.

Therefore:

Component Improvement ≠ Composite Harm Resolution

A single component becoming safe or recovered does not automatically
resolve the whole Harm.

  • Distributed Harm State


A Harm may span:

agents

systems

organizations

locations

subjects

or:

domains

HSS must remain capable of representing the complete state despite
distributed observation.

Canonical principle:

Distributed Observation ≠ Fragmented Harm Reality

  • Harm State and Producing Mechanism


The state of the mechanism that produced Harm is separate from the state
of Harm itself.

Therefore:

Mechanism Stopped ≠ Harm Stopped

System Fixed ≠ Harm Resolved

Unsafe Behavior Ended ≠ Harm Ended

This distinction is fundamental to HAGA™.

  • Harm State and Containment


Containment may stop further expansion while existing Harm remains Active.

Therefore:

Contained Harm ≠ Resolved Harm

HCOS governs Containment.

HSS represents the resulting Harm State.

  • Harm State and Mitigation


Mitigation may reduce Harm without eliminating it.

Therefore:

Mitigated Harm ≠ Resolved Harm

A Harm may move:

Active → Reduced

while remaining governed.

  • Harm State and Recovery


Recovery may change Harm toward:

Recovering

or:

Residual

but:

Recovery ≠ Automatic Resolution

HRRHS governs the Recovery process and Residual Harm determination.

  • Harm State and Propagation


HCPS governs how Harm:

changes

accumulates

compounds

propagates

or:

cascades

HSS governs the resulting current state.

Canonical boundary:

HCPS governs the dynamics of Harm change. HSS governs the state produced
by those dynamics.

  • State Monitoring


HSS requires sufficient monitoring to determine whether the current state
remains valid.

Monitoring may be:

continuous

periodic

event-triggered

condition-triggered

or:

reassessment-based

depending on the Harm.

  • Monitoring Frequency


Monitoring frequency should correspond to the rate and materiality with
which the Harm State may change.

A rapidly changing Harm may require substantially different monitoring
from a stable long-duration Harm.

Canonical principle:

Monitoring cadence must follow Harm dynamics, not administrative
convenience.

  • Monitoring ≠ Surveillance


HSS does not establish unlimited authority to collect information about
affected subjects.

Monitoring must remain within legitimate governance, privacy, identity,
legal, and data boundaries.

The need to govern Harm does not erase other governance constraints.

  • State Signal


A State Signal is information indicating that the current Harm State may
have changed.

A signal may arise from:

subject report

measurement

operational observation

system detection

environmental change

new effect

intervention result

or:

other governed information

Canonical distinction:

State Signal ≠ State Transition

  • State Reassessment


A material State Signal may trigger reassessment.

Reassessment determines whether:

the current state remains valid

a transition occurred

classification should change

or:

additional information is required

  • State Confidence


Where useful, HSS may associate confidence with Harm State classification.

Confidence must remain separate from:

Harm severity

Determination State

and:

state itself

Therefore:

State Confidence ≠ Harm State

  • State Uncertainty


Where the current state cannot be represented precisely, HSS must preserve
uncertainty rather than force false classification.

Examples include:

Active / Escalation Uncertain

Reduced / Persistence Uncertain

Recovering / Residual Extent Unknown

Uncertainty is a governance property, not a reason to abandon state
governance.

  • State Correction


Where a Harm State was incorrectly classified, HSS must support
correction.

The record should preserve:

previous classification

corrected classification

reason

time

and:

governed basis

Correction must not erase history.

  • Historical State Continuity


HSS must preserve the Harm State trajectory.

For example:

Active → Escalating → Stabilized → Reduced → Recovering → Residual

This trajectory is itself important governance information.

Canonical principle:

Current Harm State ≠ Complete Harm State History

  • Historical State ≠ Current State


A Harm once classified as Escalating must not remain operationally treated
as Escalating after sufficient basis establishes Reduced.

Likewise, a Harm once Reduced must not remain assumed Reduced if new
evidence establishes renewed escalation.

Current governance must reflect current state while preserving history.

  • State Change Without Cause Determination


HSS may establish that Harm changed even where the precise reason for the
change remains unresolved.

Therefore:

Harm State Change ≠ Complete Causal Explanation

The state can remain governable without HSS becoming a general causation
architecture.

  • Harm State and Severity


Severity may be an important Harm characteristic.

But severity and lifecycle state are different dimensions.

For example:

Severe + Stabilized

Moderate + Escalating

Low + Active

may all be legitimate combinations.

Therefore:

Harm Severity ≠ Harm State

  • Harm State and Risk


Risk concerns possible future outcomes.

Harm State concerns Harm that is already governed.

Therefore:

Risk State ≠ Harm State

Potential future Harm must not silently become existing Harm through state
classification.

  • Predicted State ≠ Current State


Predictive systems may forecast:

likely escalation

likely recovery

or:

likely persistence

But:

Predicted Harm State ≠ Current Governed Harm State

Prediction may inform monitoring and preparation.

It does not replace current-state governance.

  • Simulated State ≠ Actual State


SIMULOS® may simulate possible Harm trajectories.

But:

Simulated Harm State ≠ Actual Harm State

HSS must preserve the actual-world boundary.

  • Evidence Boundary


ADIT® may govern evidence used to support State classification and
transition.

HSS governs what that evidence means for the current Harm State.

Therefore:

Evidence State ≠ Harm State

  • Validation and Integrity Boundaries


VALIDOS™ may establish whether relevant state information is sufficiently
validated.

INTEGROS® may establish integrity conditions.

HSS may rely on those outputs.

But:

Validation State ≠ Harm State

and:

Integrity State ≠ Harm State

  • Operational Reality Boundary


ORA™ may establish the current operational condition of systems involved
in Harm.

But:

Operational State ≠ Harm State

A system may return to normal operation while Harm remains Active,
Recovering, or Residual.

  • Accountability and Liability Boundaries


The current Harm State does not determine:

who is accountable

who is responsible

or:

who is legally liable

Therefore:

Harm State ≠ Accountability State

Harm State ≠ Liability State

A Harm can remain Active even where no accountable or liable actor has
been established.

  • Governance Requirements


HSS requires that:

  • every Harm State remain linked to a Governed Harm Record
  • Harm Determination remain separate from Harm State classification
  • the canonical states Emerging, Active, Escalating, Stabilized,


Reduced, Recovering, Residual, and Resolved remain semantically
distinguishable; - state classification reflect the current governed Harm
condition; - state change not automatically create a new Harm identity; -
observation gaps not automatically terminate Harm; - reduced visibility
not automatically establish Harm reduction; - Harm State transitions
remain historically traceable; - non-linear transitions and regression
remain governable; - recurrence remain distinguishable from new Harm
emergence; - intermittent Harm remain governable; - multi-dimensional,
subject-level, collective, composite, and distributed states remain
representable; - mechanism termination remain separate from Harm
termination; - Containment, Mitigation, Recovery, Resolution, and Finality
remain distinct; - monitoring cadence correspond to Harm dynamics; - State
Signals remain distinct from State Transitions; - uncertainty and
confidence remain explicitly governable; - corrections preserve historical
state integrity; - severity, risk, prediction, and simulation remain
separate from current Harm State; - architecture boundaries with HCPS,
ADIT®, VALIDOS™, INTEGROS®, ORA™, AGA™, and SIMULOS® remain preserved.

  • Governance Logic


HSS applies the following logic:

Does a Governed Harm Record exist?

If no:

→ Harm State governance is not formally established through HSS.

If yes:

→ identify the current governed Harm object.

What materially supportable condition currently represents that Harm?

→ classify the Harm State.

Is the state still materially supported?

If yes:

→ preserve state persistence.

If uncertain:

→ preserve uncertainty and increase or adjust monitoring where
appropriate.

Has a material State Signal appeared?

If no:

→ continue governed monitoring.

If yes:

→ reassess the state.

Has the Harm materially worsened?

→ consider Escalating.

Has it stopped worsening without materially reducing?

→ consider Stabilized.

Has the Harm materially decreased?

→ consider Reduced.

Is governed Recovery underway?

→ consider Recovering.

Does Harm remain after material Recovery?

→ consider Residual.

Have applicable Resolution conditions been satisfied?

→ consider Resolved, subject to HRFS governance.

Does the apparent change actually represent propagation, accumulation,
compounding, or cascading?

→ hand the relevant dynamic to HCPS.

Does the apparent state change require a new Harm identity?

→ return to the relevant Boundary / Emergence governance rather than
silently create or merge Harm objects.

At every stage:

State Change ≠ New Harm by Default

No Observation ≠ No Harm

Mechanism End ≠ Harm End

Reduced ≠ Resolved

Resolved ≠ Finality

  • Canonical Boundary


The Harm State Standard (HSS) governs the identification, classification,
persistence, duration, monitoring, uncertainty, confidence, reassessment,
correction, transition, regression, recurrence, and historical continuity
of the current state of a formally governed Harm object. It does not
determine whether Harm originally exists, recreate Harm Recognition or
Determination, redefine the Governed Harm Boundary, govern the mechanisms
through which Harm accumulates, compounds, propagates or cascades, perform
Containment or Mitigation, govern Recovery or Residual Harm determination,
establish Resolution or Finality, determine general causation, assign
accountability or responsibility, determine liability, govern claims or
compensation, or replace operational reality, evidence, validation,
integrity, identity, AI behavior, autonomous execution, simulation,
prediction, Value, tax-event, or jurisdiction-specific governance.

  • Canonical Closing Statement


Harm does not become static merely because it has been determined.

It may intensify, stabilize, diminish, recur, recover, persist residually,
or move toward Resolution while remaining the same governed Harm.

HSS preserves that continuity by governing Harm as a changing state rather
than repeatedly reducing reality to a binary question of whether Harm
exists.

Determination establishes the Harm. HSS governs what state that Harm is in
now.
