HSTM — Harm State Persistence Module

OOF® Origin Open Foundation®

Independent Methodological Authority

Canonical Definition

The HSTM — Harm State Persistence Module governs how an assigned Harm
State remains valid through time, how its continued applicability is
established, how persistence duration and continuity are represented, how
observation gaps and intermittent manifestation are handled, and when
persistence can no longer be legitimately assumed.

HSTM ensures that a Harm State does not disappear merely because no new
observation, report, complaint, measurement, incident, or system event has
occurred, while also preventing a previous Harm State from continuing
indefinitely after the governed basis no longer supports it.

It establishes the transition:

Governed Harm State Classification → Persistence Basis → Temporal
Continuity → Continued State Applicability → Persistence Qualification →
Governed Harm State Persistence

Its central question is:

For how long, and on what governed basis, does the currently classified
Harm State remain applicable?

  • Operational Role


HSCM establishes:

what state the Harm is in.

HSTM establishes:

whether that state continues to represent the Harm through time.

Its operational role is:

to maintain legitimate continuity of a classified Harm State until
sufficient governed information establishes transition, correction,
expiration of the applicable observation basis, or the need for
reassessment.

  • Position Within HSS


The HSS governance flow is:

State Identification → State Classification → State Persistence → State
Transition → State Monitoring

The Core Module sequence is:

HSIM → HSCM → HSTM → HSPM → HSVM

HSTM receives:

Governed Harm State Classification

It produces:

Governed Harm State Persistence

for subsequent State Transition and Monitoring governance.

  • Governed Object


The primary governed object is:

Persistence of the current classified Harm State

HSTM does not determine whether Harm originally existed and does not
assign the initial canonical State.

It governs whether an already classified State remains legitimately
applicable.

  • Foundational Persistence Principle


The foundational rule is:

A Harm State persists until governed conditions establish that it no
longer accurately represents the Harm — not merely until observation
stops.

Therefore:

No New Observation ≠ State Termination

But equally:

Previous State ≠ Permanent State

Persistence must be governed in both directions.

  • Persistence Basis


A Harm State may remain applicable where the governed basis supports
continuity through:

continued observation

known persistence characteristics

ongoing effects

subject condition

operational consequences

validated measurements

historical continuity

absence of a material transition signal where such absence is meaningful

or:

other appropriate governed information

Persistence must follow the nature of the Harm.

  • State Start


HSTM should preserve when the current State became applicable where that
time can legitimately be established.

This may differ from:

Harm Emergence Time

Recognition Time

Determination Time

record creation time

or:

classification processing time

Therefore:

State Start ≠ Classification Timestamp by Default

  • State Duration


HSTM governs the duration of the classified State.

Duration may be represented as:

known

bounded

estimated

ongoing

or:

uncertain

The system must not create artificial temporal precision where none
exists.

  • State Persistence Interval


Conceptually:

State Start → State Persistence Interval → State End / Transition

The persistence interval represents the period during which the State
remains the legitimate current representation of the governed Harm.

  • Continuous Harm


Where Harm is continuously observable or materially continuous, State
Persistence may be supported through continuing evidence of the same
condition.

For example:

Active → Active → Active

across successive observations does not require creation of new Harm
objects or new States.

Canonical principle:

Continued State Confirmation ≠ New State Creation

  • Intermittent Harm


Some Harm manifests intermittently.

Examples may include:

periodic physical effects

recurring digital disruption

episodic cognitive effects

intermittent infrastructure consequences

or:

temporally variable environmental Harm

Temporary non-manifestation must not automatically terminate the State.

Therefore:

Temporary Non-Manifestation ≠ State End

  • Latent Harm


A Harm may remain present while not currently observable through ordinary
monitoring.

Where the governed basis supports latent persistence:

Not Currently Observable ≠ No Longer Existing

HSTM must permit persistence to remain qualified by uncertainty where
direct observation is unavailable.

  • Observation Gap


An observation gap occurs when current information is temporarily
unavailable or insufficient.

HSTM must distinguish:

Harm State unknown during a gap

from:

Harm State ended

Canonical principle:

Monitoring Failure Must Not Become Harm Resolution by Default.

  • Reporting Gap


A lack of new:

complaints

reports

claims

system alerts

or:

notifications

does not itself establish State change.

Therefore:

No Report ≠ No Harm

This is particularly important where affected subjects cannot, do not, or
are no longer able to report the Harm.

  • Measurement Gap


Where measurement is interrupted:

sensor failure

data loss

system migration

provider change

or:

measurement discontinuity

must not automatically terminate State Persistence.

Technical visibility and Harm reality remain separate.

  • Mechanism Termination


The mechanism that produced Harm may cease while the Harm State persists.

For example:

Mechanism — Terminated

Harm — Active

or:

Mechanism — Terminated

Harm — Residual

Canonical distinction:

Mechanism Persistence ≠ Harm Persistence

and:

Mechanism Termination ≠ Harm State Termination

  • Organizational and Technical Continuity


State Persistence must survive irrelevant administrative or technical
boundaries.

The same Harm State must not reset merely because:

a case is transferred

a provider changes

an AI model is replaced

a database is migrated

a session ends

an agent changes

a department closes

or:

a new organization assumes responsibility

Canonical principle:

Administrative Continuity ≠ Harm Continuity, but administrative
discontinuity must not destroy Harm continuity.

  • Persistence Across Subjects and Dimensions


Complex Harm may persist differently across subjects or dimensions.

For example:

Physical Harm — Reduced

Financial Harm — Active

Subject A — Recovering

Subject B — Active

HSTM must preserve material differences rather than assign one unsupported
persistence condition to the complete Harm.

  • Collective and Distributed Persistence


Collective, composite, or distributed Harm may persist even where
individual components no longer manifest Harm.

Therefore:

Component Cessation ≠ Composite Harm State Termination

and:

Local Recovery ≠ Collective Recovery

Persistence must be evaluated at the level of the governed Harm object.

  • Persistence Confidence and Uncertainty


HSTM may qualify State Persistence with:

confidence

uncertainty

observation limitations

or:

temporal limitations

For example:

Active — Persistence Confirmed

Active — Persistence Probable / Direct Observation Limited

Residual — Persistence Duration Uncertain

Uncertainty must not silently become State termination.

  • Persistence Threshold


A State should continue only while the governed basis remains sufficient
to treat it as the current State.

HSTM therefore requires a methodological threshold between:

legitimate continuity

and:

unsupported assumption

The threshold should reflect:

Harm dynamics

expected persistence

available observation

materiality

state characteristics

and:

monitoring capability

  • Persistence Decay


For some Harm types, confidence that an old classification remains current
may decrease as time passes without sufficient new information.

This may be represented as:

State Persistence Confidence Decay

But:

Reduced Confidence ≠ State End

Declining confidence may instead trigger monitoring or reassessment.

  • Persistence Reassessment Trigger


Reassessment may be required when:

expected observation is missing

the State persists longer than expected

new contradictory information appears

monitoring quality deteriorates

the Harm environment materially changes

or:

the existing persistence basis becomes stale

The appropriate response is:

Reassess

not:

silently terminate the State

  • Persistence and Transition Boundary


HSTM governs continuation of the current State.

Once sufficient basis indicates that another State applies, State
Transition governance begins.

Canonical boundary:

HSTM governs whether the current State continues. HSPM governs movement
from one State to another.

Persistence therefore ends where a legitimate State Transition begins.

  • Persistence and Monitoring Boundary


Monitoring provides information used to evaluate persistence.

But:

Monitoring Activity ≠ State Persistence

HSVM governs systematic observation.

HSTM governs what continued information—or legitimate continuity between
observations—means for the persistence of the State.

  • Persistence and Resolution


Harm must not become Resolved merely because an existing State has not
recently been reconfirmed.

Resolution requires the applicable governance conditions.

Therefore:

Persistence Not Reconfirmed ≠ Resolved

and:

End of Monitoring ≠ End of Harm

  • Persistence and Finality


Even a Resolved State does not establish lifecycle Finality.

Therefore:

Resolved State Persistence ≠ Harm Finality

HRFS owns Resolution and Finality governance.

  • Historical Persistence


HSTM should preserve:

State start

confirmed persistence periods

observation gaps

persistence qualifications

reassessments

and:

State end or transition

This produces a traceable temporal representation of Harm.

Canonical principle:

The history of how long Harm remained in a State is part of Harm
governance.

  • Persistence Correction


If governance later establishes that a State did not persist for the
previously recorded period, HSTM must support correction.

The correction should preserve:

previous persistence representation

corrected interval

basis for correction

and:

historical trace

Correction must not silently rewrite the Harm timeline.

  • Minimum Implementation Framework


A minimum HSTM implementation requires eight capabilities.

  • State Continuity Control


Maintain the current classified Harm State while the governed basis
supports its continued applicability.

  • Temporal Persistence Representation


Preserve State start, duration, persistence interval, uncertainty, and
applicable temporal qualifications.

  • Observation-Gap Governance


Distinguish lack of observation, reporting, measurement, or monitoring
from actual State termination.

  • Intermittent & Latent Harm Support


Represent Harm whose manifestation is intermittent, latent, delayed, or
temporarily unobservable without repeatedly terminating and recreating its
State.

  • Complex Persistence Representation


Support subject-level, dimensional, collective, composite, and distributed
persistence.

  • Persistence Confidence & Reassessment


Govern uncertainty, confidence decay, stale persistence basis, and
reassessment triggers.

  • Boundary & Historical Continuity


Separate State Persistence from mechanism status, administrative
continuity, State Transition, Monitoring, Resolution, and Finality while
preserving persistence history and corrections.

  • Governed Output


Produce a traceable Governed Harm State Persistence suitable for
subsequent State Transition and Monitoring governance. 31. Use Case 1 —
Monitoring Stops but Harm Cannot Be Assumed Resolved

A governed environmental Harm is classified as:

Active

A monitoring system later fails for several weeks.

No new measurements are available.

HSTM does not convert:

Active

into:

Resolved

merely because direct observation stopped.

Instead, it preserves the State with the appropriate:

observation gap

persistence uncertainty

and:

reassessment requirement

until sufficient governed information establishes the current condition.

The governing principle is:

Loss of visibility must not become disappearance of Harm.

  • Use Case 2 — Harm Persists Across System Replacement


An AI system produces a governed Harm classified as:

Active

The model is removed, the provider changes, and the operational
environment is rebuilt.

The Harm consequence affecting the subject remains.

HSTM preserves continuity:

Harm₁ / Active → System Replacement → Harm₁ / Active

rather than resetting the Harm State because the producing infrastructure
changed.

The governing principle is:

A technical lifecycle boundary does not terminate a continuing Harm State.

  • Governance Requirements


HSTM requires that:

  • every persistent State remain linked to the correct governed Harm


identity; - State start remain distinguishable from classification
processing time; - duration and persistence intervals preserve uncertainty
where necessary; - continued confirmation not create duplicate States; -
intermittent or latent Harm not repeatedly disappear through temporary
non-manifestation; - observation, reporting, measurement, and monitoring
gaps not automatically terminate State; - mechanism termination remain
separate from Harm State termination; - technical and organizational
changes not reset legitimate Harm continuity; - subject-level and
dimensional persistence differences remain representable; - collective,
composite, and distributed Harm be evaluated at the appropriate
Harm-object level; - uncertainty and confidence remain explicit; -
declining persistence confidence trigger reassessment rather than
automatic State termination; - persistence not continue indefinitely
without sufficient methodological basis; - State Persistence remain
separate from State Transition and Monitoring; - lack of reconfirmation
not establish Resolution; - Resolution remain separate from Finality; -
persistence history and corrections remain traceable.

  • Governance Logic


HSTM applies the following logic:

Does a Governed Harm State Classification exist?

If no:

→ State Persistence cannot be formally governed.

If yes:

→ establish the State's applicable temporal starting point.

Does the governed basis continue to support the State?

If yes:

→ preserve State Persistence.

Is direct observation temporarily unavailable?

If yes:

→ record the observation gap; do not infer State termination.

Is the Harm intermittent or latent?

If yes:

→ apply the relevant persistence pattern rather than repeatedly
terminating the State.

Has the producing mechanism stopped or changed?

→ treat mechanism status separately.

Has the organization, system, provider, agent, or technical environment
changed?

→ preserve Harm continuity where the Harm remains the same.

Has persistence confidence materially degraded?

→ trigger reassessment or monitoring where appropriate.

Does sufficient governed information establish that another State now
applies?

If yes:

→ end the current persistence interval and hand off to State Transition
governance.

Is there insufficient basis either to confirm continuation or establish
transition?

→ preserve uncertainty rather than manufacture Resolution.

No Observation ≠ No Harm

Temporary Non-Manifestation ≠ State End

Mechanism End ≠ Harm State End

System Change ≠ Harm Reset

Reduced Confidence ≠ State End

Persistence Not Reconfirmed ≠ Resolved

  • Canonical Boundary


The HSTM — Harm State Persistence Module governs the temporal continuity,
duration, continued applicability, observation-gap handling, intermittent
and latent persistence, confidence, uncertainty, reassessment triggers,
correction, and historical continuity of an already classified Harm State.
It does not identify or initially classify the Harm State, independently
determine State Transition, perform systematic State Monitoring,
redetermine whether Harm exists, redefine the Governed Harm Boundary,
govern Harm accumulation, compounding, propagation or cascading, perform
Containment or Mitigation, govern Recovery or Residual Harm determination,
establish Resolution or Finality, determine general causation, assign
accountability or liability, govern claims or compensation, or replace
operational reality, evidence, validation, integrity, identity, AI
behavior, autonomous execution, simulation, prediction, Value, tax-event,
or jurisdiction-specific governance.

  • Canonical Closing Statement


Harm does not cease because observation pauses, a report is not filed, a
sensor fails, a system is replaced, or the mechanism that produced the
Harm disappears.

At the same time, no historical classification should persist indefinitely
merely because nobody formally changed it.

HSTM governs the space between those two errors.

A Harm State persists only for as long as governance can legitimately say
that it still represents the Harm.
