Canonical Definition

The Audio Origin Module (AOM™) defines how the origin of audio content
is declared using a single, clear origin code.

The module enables immediate recognition of whether audio
is human generated, AI generated, or undeclared.

Declaration

Only one origin code may be used:

  • HGA — Human Generated Audio
  • AGA — AI Generated Audio
  • UGA — Unknown Generated Audio

Usage

Audio Level (required — single code)

One origin code must be associated with the audio content.

Examples:

  • HGA
  • AGA
  • UGA

Description Level (required)

The declaration must be included in the description or metadata: 

Audio: HGA
OOF Compatible — ODS™ Standard
https://originopenfoundation.org

OOF Compatibility

Content using this module may include the statement:

OOF Compatible — ODS™ Standard

A reference link to the official source is required.

Use Case 1 — Podcast Transparency

Scenario

A podcast includes human speech, AI voice, or mixed production.

Application

The creator declares audio origin (HGA / AGA / UGA).

Result

  • Clear listener understanding
  • Increased trust
  • Transparent content production

Use Case 2 — Voice AI Content

Scenario

AI-generated voice content is used in media, narration, or automation.

Application

Audio origin is declared as AGA.

Result

  • Clear distinction from human voice
  • Reduced confusion and misuse
  • Aligned platform and audience expectations

Structural Principle

One code defines origin.
Declared origin defines trust.

Closing Statement

What is heard should not be assumed.
It should be declared.
