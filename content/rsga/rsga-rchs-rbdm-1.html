1. Canonical Definition

RBDM — Resource Boundary Definition Module governs how the boundary of a Resource or Resource System is established, represented, justified, maintained, and revised so that Resource Sustainability governance operates

upon the correct Governed Resource rather than an incomplete, expanded, contracted, or otherwise misleading representation of Resource reality.

RBDM determines what is included within the governed Resource boundary, what is excluded, which boundary dimensions are materially relevant, and under what conditions the boundary must change.

The Module prevents downstream Resource governance from relying upon a boundary selected merely because it is convenient, administratively familiar, technically easy to measure, or favorable to a preferred outcome.

The Resource boundary must follow the governed Resource reality, not the preferred analytical outcome.

2. Operational Role

Every downstream RSGA™ determination depends upon the boundary of the Governed Resource.

Availability can appear greater or smaller depending upon what Resource sources are included.

Demand can appear lower if relevant consumers are excluded.

Scarcity can disappear if a geographic boundary is artificially expanded.

Recovery performance can appear stronger if difficult recovery streams are excluded.

Resource dependency can appear weaker if external supporting Resources are ignored.

Continuity can appear secure if the analysis ends before a known future constraint.

RBDM therefore establishes the boundary within which Resource characterization can legitimately proceed.

Its operational role is to answer:

What exactly is inside the Governed Resource? What is outside it? Why is that boundary appropriate? Which dimensions define it? Which dependencies cross it? Which exclusions could materially affect downstream governance? How long does the boundary remain valid? What change would require the boundary to be reconsidered?

3. Governed Object

The primary Governed Object of RBDM is:

The boundary of a Resource or Resource System subject to RSGA™ governance.

The boundary may concern:

A Resource stock A Resource flow A Resource capacity A Resource source A Resource infrastructure A Resource recovery system A regenerative Resource A distributed Resource System A cross-Resource system

RBDM governs the boundary representation.

It does not determine the complete Resource State itself.

4. Position in Parent Standard Internal Module Flow

The Resource Characterization Standard (RCHS) begins with boundary establishment because Resource classification, state definition, origin, source, and context depend upon knowing what Resource is being characterized.

The internal module progression is:

→ RBDM — Resource Boundary Definition Module → RTCM — Resource Type & Constraint Module → RSDM — Resource State Definition Module → ROSM — Resource Origin & Source Module → RCXM — Resource Context Module

RBDM establishes the governed perimeter.

Subsequent modules characterize what exists within that perimeter.

5. Boundary Definition Requirement

Every Governed Resource must have a boundary sufficiently explicit to support downstream Resource Sustainability governance.

A boundary may be simple or multidimensional.

It must nevertheless allow a governed system to determine:

Included Resource Excluded Resource Included capacity Excluded capacity Included sources Excluded sources Relevant location Relevant time horizon Relevant system components Relevant Resource states Boundary-crossing dependencies

A Resource description without sufficient boundary information must not automatically be treated as a complete Governed Resource definition.

6. Boundary Dimensions

RBDM recognizes that Resource boundaries may require multiple dimensions.

Relevant dimensions may include:

Physical Boundary Geographic Boundary Functional Boundary System Boundary Infrastructure Boundary Source Boundary Temporal Boundary Operational Boundary Recovery Boundary Resource-State Boundary

No single dimension is universally sufficient.

The required boundary structure follows the governed reality.

7. Physical Boundary

A Physical Boundary defines the physical Resource, stock, infrastructure, material, capacity, or system components included within the Governed Resource.

It may distinguish:

Included physical stock Excluded stock Included infrastructure Excluded infrastructure Contained Resource Embedded Resource Stored Resource Recoverable Resource

Physical proximity alone does not establish inclusion.

Likewise, physical separation does not automatically establish exclusion where separated components form one materially integrated Resource System.

8. Geographic Boundary

A Geographic Boundary establishes the relevant spatial scope.

It may concern:

Facility Site Municipality Region Watershed Grid zone Network zone Country Cross-border Resource System Extraction area Storage region Regenerative habitat

Administrative geography must not automatically define the Resource boundary.

A watershed, electrical system, fish stock, transmission system, mineral supply chain, or other Resource System may cross administrative borders.

Administrative Boundary ≠ Resource Boundary.

Where the physical or operational Resource System crosses jurisdictional boundaries, RBDM must preserve that reality.

9. Functional Boundary

A Functional Boundary identifies which Resource functions are included within the governed analysis.

For example, a battery may be characterized as:

Stored energy capacity Reserve capacity Flexibility capacity Backup capacity Grid-support capacity

These functions may overlap physically while representing different Resource governance questions.

RBDM must prevent a nominal physical asset from being treated as one undifferentiated Resource where its functional capacities are materially different.

Same Asset ≠ Same Resource Function.

10. System Boundary

A System Boundary determines which components collectively form the Governed Resource System.

The boundary may include:

Sources Storage Distribution components Recovery pathways Relevant infrastructure Relevant Resource stocks Relevant capacities

System inclusion requires a material relationship to the governed Resource question.

The system must not be expanded indefinitely merely because distant dependencies exist.

Likewise, material components must not be excluded merely because they are organizationally external.

11. Infrastructure Boundary

Resource availability may depend upon infrastructure.

RBDM distinguishes the Resource from the infrastructure enabling its extraction, generation, movement, storage, recovery, or use.

Where infrastructure capacity itself is the Governed Resource, it may require its own boundary.

For example:

Electricity ≠ Transmission Capacity

Water ≠ Water Distribution Capacity

Compute Hardware ≠ Compute Capacity

Stored Material ≠ Processing Capacity

A Resource and its enabling infrastructure may therefore constitute separate but interdependent Governed Resources.

12. Source Boundary

A Source Boundary establishes which Resource sources belong within the governed Resource representation.

Relevant distinctions may include:

Primary source Secondary source Recovered source Backup source Alternative source Imported source Distributed source

A source must not be included merely because it theoretically exists.

Likewise, an external source must not be excluded merely because it lies outside the organization controlling the Resource.

Source inclusion must reflect the Resource reality relevant to the governed question.

13. Temporal Boundary

Every Resource boundary exists within a time context.

A Temporal Boundary may define:

Current operating period Peak period Season Planning horizon Recovery horizon Regeneration horizon Infrastructure lifecycle Continuity horizon

A Resource boundary valid today may not remain valid across a materially different future Resource configuration.

Boundary validity is time-dependent where the governed Resource reality changes through time.

A short temporal boundary must not be used to conceal known longer-term constraints where long-term continuity is the governed question.

14. Operational Boundary

An Operational Boundary identifies which operating conditions belong within the Governed Resource representation.

Relevant conditions may include:

Normal operation Peak operation Reduced operation Emergency operation Maintenance state Recovery state Reserve operation

A Resource System may have materially different effective boundaries under different operational conditions.

For example, backup generation or reserve storage may become part of the operational Resource System only under defined conditions.

RBDM must preserve such conditional inclusion.

15. Recovery Boundary

A Recovery Boundary determines whether residual, embedded, recoverable, recovered, or secondary Resources remain within the governed Resource lifecycle.

A boundary must not terminate automatically when the original functional use ends.

Functional End-of-Use ≠ Resource End-of-Life.

Where Resource recovery is materially possible, RBDM must permit the Resource boundary to extend beyond the first- use lifecycle.

This prevents recoverable Resource capacity from disappearing analytically merely because the original product or function has ended.

16. Resource-State Boundary

A Resource may change state without becoming an entirely different Resource.

Relevant transitions may include:

Primary → Embedded Embedded → Recoverable Recoverable → Recovered Recovered → Secondary Stored → Released Reserved → Available

RBDM must determine when a state transition remains within the same governed Resource lifecycle and when the transition creates a sufficiently distinct Governed Resource requiring a new or revised boundary.

The determination must follow material governance significance rather than naming convention alone.

17. Included Resource

Every Resource boundary must establish what is affirmatively included.

Included elements should be identifiable through the minimum structure necessary to prevent ambiguity.

Inclusion may be:

Permanent Conditional Temporal State-dependent Source-dependent Operationally dependent

Conditional inclusion must state the condition under which the Resource element enters or leaves the governed boundary.

18. Excluded Resource

Material exclusions must be explicit.

Where an excluded Resource, source, capacity, location, state, infrastructure component, or time period could materially affect downstream governance, the exclusion must be justified.

Unstated exclusion must not silently shape the governed result.

RBDM therefore treats exclusion as a governance decision where it materially affects the Resource representation.

19. Boundary Exclusion Test

A proposed exclusion should be tested against the following question:

Could excluding this element materially change a downstream determination concerning availability, demand, dependency, access, allocation, consumption, scarcity, recovery, substitution, resilience, continuity, or sustainability?

If No , exclusion may be methodologically immaterial.

If Yes , exclusion requires explicit justification.

If Unknown , the boundary remains uncertain until sufficient evidence supports treatment.

20. Boundary Inclusion Test

A proposed inclusion should be tested against:

Does this element materially belong to the Resource or Resource System required to answer the governed Resource Sustainability question?

Inclusion must not occur solely because the element:

is nearby; belongs to the same organization; shares ownership; shares infrastructure; is technically measurable; improves the apparent Resource state; reduces apparent scarcity; improves apparent sustainability.

The inclusion must have a defensible relationship to the Governed Resource.

21. Boundary Materiality

Not every boundary difference is governance-relevant.

RBDM applies a materiality principle.

A boundary characteristic is material when changing it could reasonably alter:

Resource characterization Availability Capacity Demand relationship Dependency Criticality Access Priority Allocation Consumption interpretation Scarcity state Recovery potential Substitution options Resilience Continuity Sustainability

Immaterial detail should not be elevated into unnecessary governance complexity.

Boundary precision must be sufficient for the governed decision, not infinite.

22. Boundary Evidence

A Resource boundary must be supported by sufficient evidence appropriate to the governed Resource.

Evidence may concern:

Physical configuration Technical system structure Geographic reality Resource source Operational relationship Infrastructure relationship Recovery pathway

Temporal condition Regeneration system Resource flow

RBDM establishes the evidence requirement relevant to Resource Boundary Definition.

It does not replace Audit and Evidence Governance.

Where evidence is insufficient, the boundary must remain qualified rather than fabricated.

23. Boundary Provenance

The governed boundary must remain traceable to the information and determinations upon which it was established.

Relevant provenance may include:

Source evidence Boundary rationale Boundary version Effective period Known assumptions Material exclusions Material inclusions Responsible determination reference Revisions

Boundary provenance allows later reassessment when evidence changes.

24. Boundary Uncertainty

A Resource boundary may be uncertain.

Uncertainty may concern:

Physical extent Resource ownership context Source relationship Geographic scope System inclusion Recovery potential Temporal validity Operational inclusion State transition

RBDM must preserve material boundary uncertainty.

Possible states may include:

Boundary Established Boundary Conditionally Established Boundary Partially Established Boundary Evidence-Limited Boundary Conflicted Boundary Unresolved

Boundary uncertainty must not be converted into false boundary precision.

25. Boundary Assumptions

Where boundary definition depends upon an assumption, that assumption must be visible if it could materially affect downstream governance.

Examples may include assumed:

Source availability System integration Recovery inclusion Operational configuration Geographic coverage Temporal stability

An assumption is not evidence merely because it is operationally convenient.

Boundary Assumption ≠ Boundary Evidence.

26. Boundary Manipulation Risk

Resource boundaries can materially influence governance outcomes.

RBDM therefore recognizes boundary manipulation as a methodological risk.

Manipulation may include:

Boundary Expansion — including favorable Resource capacity that is not legitimately part of the governed Resource.

Boundary Contraction — excluding constrained, depleted, inaccessible, or problematic Resource conditions.

Temporal Truncation — selecting a favorable period while excluding known future constraint.

Geographic Shifting — moving Resource impact or scarcity outside the analytical boundary.

Recovery Exclusion — ending the Resource lifecycle before recoverable Resource is considered.

Dependency Exclusion — ignoring external Resources required for the Governed Resource to remain functional.

Capacity Inflation — including nominal capacity that cannot legitimately function as available or usable Resource capacity.

RBDM must make such distortions detectable.

27. Boundary Expansion

Boundary Expansion is legitimate only where the added element materially belongs to the governed Resource question.

Expansion may be required following:

New source integration Infrastructure integration Recovery pathway activation Resource-System expansion Cross-border system recognition Newly identified Resource component

Expansion must not be used merely to dilute scarcity or increase apparent capacity.

28. Boundary Contraction

Boundary Contraction may be legitimate where an element no longer belongs to the Governed Resource.

Examples may include:

Permanent source disconnection Infrastructure separation Resource-System restructuring

Material state transition Expired temporal scope

Contraction must not remove materially relevant Resource conditions merely because they weaken a preferred conclusion.

29. Boundary Crossing

Resources, flows, dependencies, or capacities may cross the Governed Resource boundary.

RBDM must preserve material boundary-crossing relationships.

Relevant crossing may include:

Resource inflow Resource outflow Imported Resource Exported Resource External storage External recovery External infrastructure dependency Cross-border flow Cross-system dependency

A boundary does not imply isolation.

Boundary Definition ≠ Dependency Elimination.

30. Cross-Resource Boundary

Where multiple Resources interact, each Resource retains its own boundary unless a justified Resource-System boundary is established.

For example:

Water Electricity Cooling Capacity Compute Capacity

may form an interdependent system without becoming one physically equivalent Resource.

RBDM must preserve both:

Individual Resource Boundaries

and, where justified:

Shared Resource-System Boundary

System Integration does not erase Resource distinction.

31. Nested Boundaries

RBDM permits nested Resource boundaries where different governance scales require them.

Example:

Data Center Cooling Capacity ⊂ Facility Resource System ⊂ Regional Infrastructure Resource System

or:

Local Water Source ⊂ Watershed Resource System ⊂ Regional Water Resource System

Nested boundaries must preserve the relationship between levels.

A local boundary must not automatically inherit the Resource state of the wider system, nor vice versa.

32. Multi-Scale Boundary Governance

A Resource may be governed at:

Asset / Facility Level Organization Level Infrastructure Level Resource-System Level Sector Level Regional Level Cross-Resource System Level

The appropriate boundary depends upon the governance question.

Different scales may legitimately produce different Resource states because they represent different Governed Objects.

Different Scale ≠ Conflicting Result when the Governed Resource boundary differs legitimately.

Scale must therefore always remain visible.

33. Organizational Boundary

Organizational control does not define Resource reality by itself.

A Resource System may extend beyond the organization that operates or consumes it.

Likewise, an organization may control multiple Resource Systems that should not be merged.

Organizational Boundary ≠ Resource Boundary.

This distinction is particularly important for utilities, infrastructure systems, supply chains, cloud infrastructure, water systems, energy systems, and shared Resource networks.

34. Jurisdictional Boundary

Legal or jurisdictional borders may be relevant to authority, access, allocation, or compliance.

They do not automatically establish the physical Resource boundary.

A Resource may cross multiple jurisdictions.

RBDM preserves the Resource boundary while allowing jurisdictional context to be represented separately.

Jurisdictional Boundary ≠ Physical Resource Boundary.

Where jurisdiction materially affects Resource access or allocation, that relevance is governed downstream under the applicable governance space.

35. Ownership Boundary

Ownership may provide important context.

It does not establish the Resource boundary automatically.

Multiple owners may participate in one Resource System.

One owner may control multiple distinct Resources.

RBDM therefore distinguishes:

Resource Boundary Ownership Boundary Control Boundary Authority Boundary

These may overlap.

They must not be presumed identical.

36. Regenerative Resource Boundary

Regenerative Resources require boundaries capable of preserving relevant regenerative reality.

A fish stock, forest, biomass system, or comparable Resource may not align with property, administrative, or organizational boundaries.

Relevant boundary factors may include:

Population or stock structure Habitat or geographic range Regeneration system Seasonal movement Extraction region Relevant time horizon

Specialized biological or ecological domains determine the underlying scientific reality.

RBDM governs how that reality informs the RSGA™ Resource boundary.

37. Recoverable Resource Boundary

Recoverable Resources may persist beyond the first functional lifecycle.

RBDM must permit boundaries that include:

Embedded material Residual material Recovery stream Recovered material Secondary Resource

where materially relevant.

A product leaving active use does not automatically remove its embedded Resources from Resource Sustainability governance.

38. Capacity Boundary

Capacity Resource boundaries must distinguish the capacity being governed from related nominal infrastructure.

For compute, storage, networks, energy, cooling, or comparable capacity systems, relevant boundary characteristics may include:

Installed capacity Operationally connected capacity Reserved capacity Technically usable capacity Resource-specific capability Location Time Supporting dependencies

RBDM defines which capacity belongs within the Governed Resource.

Subsequent RSGA™ governance determines how much is actually available, usable, or allocable.

39. Boundary Change

A previously valid boundary may become invalid following material change.

Potential triggers include:

New source Source loss Infrastructure expansion Infrastructure disconnection Geographic change Operational reconfiguration Recovery pathway activation Resource-State transition System merger System separation Material dependency discovery Material temporal change

Boundary validity must therefore be reassessable.

40. Boundary Versioning

Where a material boundary change occurs, the revised boundary must be distinguishable from the prior boundary.

A boundary revision should preserve:

Previous boundary Revised boundary Change reason Effective point Affected elements Material downstream implications

Historical Resource assessments must remain interpretable against the boundary under which they were produced.

Changed Boundary ≠ Same Governed Object Representation.

41. Boundary Reassessment Trigger

A boundary reassessment must be considered when new evidence indicates that the existing boundary may no longer represent the governed Resource sufficiently.

Canonical trigger logic:

Existing Boundary → New Evidence / Material Change → Boundary Impact Test

→ Boundary Retained or Revised → Characterization Impact → Downstream Reassessment Trigger where material

A boundary change should not automatically invalidate every downstream result.

It must identify which results materially depend upon the changed boundary.

42. Boundary Comparability

Resource assessments must not be treated as directly comparable where their underlying boundaries differ materially unless the difference has been governed.

Before comparison:

Boundary A ↔ Boundary B → Boundary Equivalence Test → Comparable / Conditionally Comparable / Not Comparable

Same Resource Name ≠ Same Resource Boundary.

This principle is critical for comparing facilities, regions, organizations, reporting periods, or Resource Systems.

43. Boundary Equivalence

Two Resource boundaries may be considered equivalent only where their differences do not materially alter the governance question being compared.

Boundary equivalence may require alignment of:

Resource definition Geographic scope Temporal scope Functional scope System scope Source inclusion Recovery inclusion Relevant Resource states

Physical identity alone is insufficient.

44. Boundary and Normalization

Normalization must not conceal material boundary differences.

Before cross-Resource or cross-system normalization, the relevant Resource boundary must be known.

Normalization cannot repair an invalid Resource boundary.

Where boundaries differ materially, the difference must either be governed before normalization or preserved as a limitation upon comparability.

45. Boundary and Scarcity

Scarcity can be highly boundary-sensitive.

A Resource may appear abundant globally while being severely constrained locally.

Likewise, local abundance may depend upon external Resource flows.

RBDM therefore prevents scarcity governance from relying upon an unspecified geographic, system, or temporal boundary.

Resource Abundance at one boundary does not establish Resource Availability at another.

46. Boundary and Recovery

Recovery performance may be distorted if Resource boundaries end at functional disposal.

RBDM requires recovery-relevant boundaries to preserve residual and embedded Resource where materially relevant.

This allows downstream RSGA™ governance to determine actual Recovery Potential without artificially terminating the Resource lifecycle.

47. Boundary and Interdependency

Resource boundaries must not hide dependencies crossing them.

A facility may have a clear physical boundary while depending upon external:

Electricity Water Cooling infrastructure Network capacity Materials Storage Transport

RBDM records the boundary.

Resource Interdependency governance later determines the significance of those relationships.

A bounded Resource System may remain externally dependent.

48. Boundary and Continuity

Long-term Resource Continuity cannot be established solely from a boundary optimized for present operation.

Where continuity is being governed, boundary definition must remain capable of representing known future changes relevant to that horizon.

A boundary that is sufficient for immediate operation may therefore be insufficient for long-term sustainability analysis.

49. Boundary Conflict

Different legitimate actors may propose different Resource boundaries.

A conflict may arise between:

Technical boundary Operational boundary Administrative boundary Geographic boundary Ecological boundary Commercial boundary Reporting boundary

RBDM does not assume one category always dominates.

The correct boundary is the one that legitimately represents the Governed Resource for the relevant Resource Sustainability question.

Where multiple boundaries remain materially relevant, they may need to coexist as explicitly differentiated Governed Objects.

50. Boundary Resolution

Boundary conflict should be resolved through:

Governed Question → Competing Boundary Representations → Evidence → Materiality Analysis → Resource-Reality Alignment → Boundary Determination → Residual Uncertainty

Resolution must not be based solely upon institutional preference or analytical convenience.

51. Minimum Boundary Representation

At minimum, a governed Resource boundary should identify, where applicable:

Governed Resource Boundary type Included elements Excluded material elements Geographic scope Temporal scope Functional or system scope Relevant source scope Relevant state scope Boundary-crossing dependencies Boundary assumptions Boundary uncertainty Boundary evidence reference Boundary version

Additional information should be required only where necessary for the governed reality.

52. Boundary Sufficiency State

RBDM may produce a Boundary Sufficiency State.

Possible states include:

Boundary Sufficient Boundary Conditionally Sufficient Boundary Partially Sufficient Boundary Evidence-Limited Boundary Conflicted Boundary Insufficient Boundary Unresolved

Boundary sufficiency concerns whether the Resource boundary is adequate for downstream governance.

It does not establish that the Resource itself is available, sustainable, or legitimate to consume.

53. Boundary Failure Conditions

A Resource boundary should not be treated as sufficient where:

Material Resource elements remain undefined Material exclusions are hidden Material inclusions lack justification Geographic scope is materially ambiguous Temporal scope is materially ambiguous Relevant Resource states are conflated Resource and infrastructure are improperly merged Cross-boundary dependencies are concealed Boundary assumptions materially determine the outcome without disclosure Boundary evidence is materially insufficient Boundary manipulation materially distorts downstream governance

Such conditions require correction, qualification, or escalation before dependent determinations are relied upon.

54. Governance Requirements

A conforming RBDM implementation must:

1. identify the Resource whose boundary is being defined; 2. identify the relevant boundary dimensions; 3. establish explicit inclusion; 4. establish material exclusion; 5. preserve relevant geographic scope; 6. preserve relevant temporal scope; 7. preserve functional and system scope where applicable; 8. distinguish Resource from enabling infrastructure where materially necessary; 9. preserve Resource-State boundaries where relevant; 10. preserve recovery-relevant Resource beyond functional end-of-use where applicable; 11. identify material boundary-crossing dependencies; 12. disclose material boundary assumptions; 13. preserve material boundary uncertainty; 14. support evidence-backed boundary justification; 15. prevent outcome-driven boundary manipulation; 16. support boundary versioning; 17. support reassessment following material change; 18. prevent invalid comparison across materially different boundaries; 19. preserve specialized-domain ownership of underlying physical mechanisms; 20. produce a governed Boundary Sufficiency State.

55. Governance Logic

Canonical RBDM governance logic:

Candidate Resource → Governed Resource Question → Boundary Dimensions → Proposed Inclusion → Proposed Exclusion → Materiality Test → Resource-Reality Alignment → Boundary Evidence → Boundary Assumptions → Boundary Uncertainty → Boundary Determination → Boundary Sufficiency State → Governed Resource Boundary

Where uncertainty remains:

Boundary Uncertainty → Missing Evidence → Additional Evidence / Specialized Domain Input → Boundary Reassessment

Where change occurs:

Existing Boundary → Material Change → Boundary Impact Test → Revised Boundary where required → Characterization Impact → Downstream Reassessment

58. Cross-Architecture Boundary

RBDM may consume operational, scientific, technical, geographic, infrastructural, ecological, or other governed inputs necessary to establish Resource reality.

It does not acquire governance over those originating domains.

GOA™ remains responsible for Governance Authority.

ORA™ remains responsible for general Operational Reality.

ADIT® remains responsible for Audit and Evidence Governance.

VALIDOS™ remains responsible for general Validation Governance.

PGA™ remains responsible for governed Prediction where future Resource conditions are predicted.

Specialized Resource architectures remain responsible for their Resource-specific operational mechanisms.

RBDM governs only the boundary required for Resource Sustainability governance.

59. Cross-Architecture Mechanism Principle

An operational mechanism may produce inputs for multiple governance architectures, but it belongs only to the architecture whose governed domain includes that mechanism itself. Other architectures govern only its domain-specific relevance or consequences.

Applied to RBDM:

A hydrological model may establish the physical extent of a water system.

A grid model may establish relevant electricity-system structure.

A biological model may establish the relevant extent of a fish stock.

A compute topology may establish relevant infrastructure relationships.

RBDM may use those governed outputs to establish the Resource boundary.

It does not govern the underlying hydrology, grid physics, biology, or compute engineering.

60. Canonical Boundary

RBDM governs how the boundary of a Resource or Resource System is established and maintained for Resource Sustainability governance. It does not determine the downstream availability,

entitlement, allocation, consumption, scarcity, recovery viability, resilience, or sustainability of the Resource itself.

The Module ends when the Resource boundary is sufficiently established, qualified, evidenced, and represented for the remaining Resource Characterization governance to proceed.

61. Canonical Closing Statement

A Resource assessment is only as legitimate as the boundary that defines what the assessment actually includes.

RBDM prevents Resource Sustainability governance from beginning with the wrong Resource.
