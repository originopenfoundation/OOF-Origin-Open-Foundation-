1. Canonical Definition

PKDM — Peak Demand Module governs how the highest materially relevant Resource Demand occurring within a defined governance interval is identified, measured, bounded, temporally located, functionally attributed, evidenced, qualified, and reassessed so that historical extremes, instantaneous spikes, theoretical maxima, installed consumption capability, requested capacity, or isolated anomalies are not automatically treated as governed Peak Demand.

PKDM establishes the Peak Demand State within RDGS.

Maximum Observed Value ≠ Governed Peak Demand by definition.

2. Operational Role

CRDM establishes the Core Resource Demand object.

FDIM establishes the functional structure of that Demand.

PKDM determines the materially relevant upper Demand condition.

Its role is to establish:

whether Peak Demand exists; how much Resource is required at Peak; when the Peak occurs; how long it lasts; which function or functions create it; whether it is recurring, seasonal, conditional, event-driven, or anomalous; which measurement interval defines it; which evidence supports it; and how certain the Peak Demand representation is.

PKDM prevents Resource governance from treating a single high number as sufficient evidence of Peak Demand.

3. Core Question

What is the highest materially relevant Resource Demand within the governed interval, when does it occur, how long does it persist, what creates it, and what evidence establishes that it represents a governable Peak rather than an isolated or misleading maximum?

4. Position in RDGS Module Flow

CRDM — Core Resource Demand Module → FDIM — Functional Demand Identification Module → PKDM — Peak Demand Module → CPDM — Concurrent & Parallel Demand Module → DCMM — Demand Consolidation & Management Module

PKDM establishes the Peak Demand structure before multiple Demand objects are evaluated for concurrency and consolidated Resource Demand.

5. Governed Space

PKDM governs:

Peak Resource Demand Governance

This space concerns the highest materially relevant Resource requirement within defined temporal, functional, spatial, operational, and evidentiary conditions.

6. Governed Object

The primary Governed Object is:

A Peak Resource Demand State associated with a governed Resource Demand or Functional Demand Profile.

The Governed Object may include:

Peak quantity; Peak capacity; Peak rate; Peak interval; Peak duration; Peak frequency; Peak recurrence; Peak function; Peak operating state; Peak location;

Peak evidence; Peak uncertainty.

7. Scope

PKDM applies wherever Resource Demand varies and the upper Resource requirement materially affects downstream Resource governance.

Its Scope includes:

Peak Demand identification; Peak Demand measurement; Peak interval definition; Peak duration; Peak timing; Peak frequency; Peak recurrence; Peak seasonality; Peak operating state; Peak functional attribution; Peak spatial context; Peak Resource quality or performance conditions where relevant; historical Peak Demand; current Peak Demand; recurring Peak Demand; conditional Peak Demand; event-driven Peak Demand; predicted Peak Demand; simulated Peak Demand; Peak evidence; Peak anomalies; Peak uncertainty; Peak sufficiency; Peak reassessment; Peak versioning.

PKDM does not independently determine:

Demand concurrency across independent Demand objects; final Demand consolidation; Resource Dependency; Criticality; Access authorization; Priority; Allocation; Consumption governance; Scarcity response; Resilience; Sustainability.

9. Peak Demand

Peak Demand is the highest materially relevant Resource requirement within a defined governance interval under specified operating conditions.

Peak Demand requires both:

Magnitude

and:

Context.

11. Peak Time

Peak Time identifies when the Peak Demand occurs.

12. Peak Duration

Peak Duration identifies how long the Peak or Peak-level condition persists.

Examples:

1 minute

14. Measurement Interval Principle

Peak Demand depends upon the measurement interval.

A one-second Peak may differ materially from a fifteen-minute Peak or hourly Peak.

Peak Window Start → Peak Demand Condition → Peak Window End

17. Peak Boundary Integrity

18. Peak Demand vs Maximum Observed Value

The maximum observed measurement may be relevant evidence.

It is not automatically the governed Peak Demand.

Maximum Observed Value ≠ Governed Peak Demand by definition.

instantaneous; short-duration; sustained; recurring; persistent during a defined operating state.

operational cycles; daily cycles; weekly cycles; seasonal cycles; production cycles; workload patterns.

33. Functional Peak

A Functional Peak represents the highest materially relevant Resource Demand attributable to a specific function.

34. System Peak

A System Peak represents the highest Resource requirement across the relevant system boundary.

35. Functional Peak vs System Peak

The Peak of one function may occur at a different time from the Peak of the entire system.

Functional Peak ≠ System Peak.

36. Component Peaks

Individual components may each have Peak Demand.

Their Peaks must not automatically be added.

37. Non-Simultaneous Peaks

If Component A peaks at Time 1 and Component B peaks at Time 2:

Peak A + Peak B ≠ System Peak by definition.

CPDM performs detailed concurrency governance.

38. Coincident Peak

A Coincident Peak occurs when multiple relevant Demand components reach materially high Demand during the same temporal interval.

PKDM may identify the condition.

CPDM determines concurrency structure across Demand objects.

39. Non-Coincident Peak

Peak Demand components may occur separately.

Their individual maxima should remain distinct.

40. Peak Diversity

Differences in timing between functional or system Peaks may materially reduce combined Peak Demand.

PKDM preserves the Peak timing required for later concurrency analysis.

41. Baseline Demand

Baseline Demand provides a reference against which Peak Demand may be interpreted.

42. Peak-to-Baseline Relationship

PKDM may represent:

Peak Demand / Baseline Demand

where useful.

The ratio is descriptive unless a governed interpretation is separately defined.

43. Average Demand

Average Demand may provide context for Peak Demand.

It must not replace Peak Demand where infrastructure must support the Peak.

44. Peak-to-Average Relationship

A Resource system may exhibit a high Peak-to-Average relationship.

This may materially affect Resource capacity requirements.

45. Average Demand Boundary

Average Demand ≠ Peak Demand.

A system that satisfies average Demand may still fail at Peak.

46. Minimum Demand vs Peak Demand

Minimum and Peak Demand represent different operating conditions.

Neither should be used as a substitute for the other.

47. Installed Consumption Capability

Installed Resource consumption capability may establish an upper technical boundary.

It does not establish Peak Demand.

Installed Capability ≠ Peak Demand.

48. Rated Maximum

A system's rated maximum Resource input does not automatically represent its governed Peak Demand.

49. Theoretical Maximum

A theoretical maximum represents what may be technically possible under defined assumptions.

Theoretical Maximum ≠ Governed Peak Demand.

50. Requested Peak Capacity

A participant may request Resource capacity intended to cover expected Peaks.

Requested Peak capacity is not automatically validated Peak Demand.

51. Contracted Capacity

Contracted Resource capacity may exceed or fall below actual Peak Demand.

Contracted Capacity ≠ Peak Demand.

52. Historical Peak

54. Historical Extreme

69. Peak Measurement Resolution

73. Resource-Specific Peak Interval

74. Peak Duration Significance

A Peak lasting one second may have different governance significance from the same magnitude sustained for six hours.

Same Peak Magnitude ≠ Same Peak Condition.

75. Peak Energy or Quantity Requirement

Where relevant, PKDM should preserve both:

and:

total Resource quantity consumed or required during the Peak interval.

76. Peak Ramp

Demand may increase rapidly toward Peak.

The rate of change may matter for Resource Systems unable to respond instantaneously.

77. Ramp-Up Condition

78. Ramp-Down Condition

79. Peak Plateau

Some Resource systems reach a sustained high-demand plateau rather than a single sharp maximum.

80. Multi-Peak Pattern

81. Primary Peak

82. Secondary Peak

83. Peak Cluster

97. Fault-Induced Peak

A fault may cause Resource Demand to rise.

98. Abnormal Peak

An abnormal Peak may be real without being representative of expected normal operation.

99. Peak Anomaly

A Peak Anomaly is a high Demand observation whose relationship to the governed Resource requirement is uncertain or inconsistent with established operating patterns.

100. Anomaly ≠ Invalid Peak

An anomalous Peak should be investigated.

It should not automatically be discarded.

101. Measurement Error

A high observation caused by measurement error must not become Peak Demand.

102. Data Quality

145. Peak Demand Integrity Principle

Peak Demand must represent the highest materially relevant Resource requirement under defined conditions, not simply the largest number available in the dataset.

146. Temporal Integrity Principle

A Peak without its measurement interval, timing, and duration is an incomplete Resource Demand representation.

147. Functional Integrity Principle

Where function materially explains the Peak, Peak Demand must remain traceable to the function that creates it.

148. Evidence Integrity Principle

An extreme observation does not become governed Peak Demand until its Resource meaning is sufficiently evidenced.

158. Use Case 1 — AI Data Center Electricity Peak Demand

FDIM establishes normal electricity Demand across an AI data center:

AI compute → 41 MW

Cooling → 10 MW

Storage & networking → 3 MW

Shared infrastructure → 4 MW

Normal combined Demand is approximately:

58 MW.

Operational telemetry records several short observations above:

72 MW.

PKDM determines that some are sub-second startup transients while recurring high-load AI training windows produce:

66–68 MW

for:

35–50 minutes

during defined workload periods.

The governed Peak Demand is therefore not established simply by selecting the maximum 72 MW observation.

PKDM preserves:

Peak magnitude; measurement interval; duration; function; operating state; recurrence; evidence.

The highest electricity reading is not automatically the data center's governed Peak Demand.

159. Use Case 2 — Regional Water Peak Demand

A region has average water Demand of:

120,000 m³/day.

During summer, Resource Demand regularly rises.

Historical records include an isolated maximum of:

182,000 m³/day

during an exceptional event.

Recurring summer high-demand periods show:

155,000–165,000 m³/day

under comparable current operating conditions.

PKDM distinguishes:

annual average Demand; recurring seasonal Peak; isolated historical extreme; future predicted Peak.

The resulting Peak Demand Profile preserves the relevant seasonal Peak range and the exceptional event separately.

An exceptional historical maximum does not automatically define the Resource capacity required for every future Peak condition.

It does not absorb their governed mechanisms.

162. Cross-Architecture Mechanism Principle

An operational mechanism may produce inputs for multiple governance architectures, but it belongs only to the architecture whose governed domain includes that mechanism itself. Other architectures govern only its domain- specific relevance or consequences.

A workload scheduler may create compute Peaks.

Weather conditions may contribute to cooling or electricity Peaks.

Production cycles may create material or energy Peaks.

Hydrological or infrastructure conditions may influence water Demand Peaks.

PKDM governs the resulting Peak Resource Demand representation.

It does not absorb the mechanisms producing those conditions.

163. Canonical Boundary

PKDM governs how the highest materially relevant Resource Demand within a defined governance interval is identified, measured, temporally bounded, functionally attributed, evidenced, qualified, and reassessed, including its magnitude, timing, duration, recurrence, operating state, location, uncertainty, and evidentiary status.

It does not determine Demand concurrency across independent Demand objects, final Demand consolidation, Resource Dependency, Criticality, Access authorization, Priority, Allocation, Consumption governance, Scarcity response, Resilience, or Sustainability.

Its principal governed output is the Peak Demand Profile used by subsequent RDGS Core Modules.

164. Canonical Closing Statement

Peak Demand is not simply the largest number found in a Resource dataset.

PKDM establishes which high-demand condition actually matters — how much Resource is required, when the Peak occurs, how long it lasts, what creates it, whether it recurs, and what evidence proves that the Peak belongs to the governed Resource reality.
