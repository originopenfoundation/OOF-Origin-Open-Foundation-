1. Canonical Definition

The Cognitive Efficiency Module (CGEM) governs whether the cognitive work performed by an intelligence execution is necessary, sufficient, proportionate, and appropriately bounded relative to the Operational Requirement, the Governed Problem-Space Efficiency State, the required validated outcome, and applicable governed constraints.

CGEM governs the computational work associated with reasoning, inference, deliberation, planning, interpretation, synthesis, comparison, uncertainty resolution, and other cognitive operations required to transform a governed problem into an actionable execution result.

It determines whether an execution performs too little cognition to satisfy the requirement, sufficient cognition to produce the required outcome, or materially more cognitive work than the outcome justifies.

CGEM does not pursue minimum reasoning.

It governs:

minimum sufficient cognitive work.

Its principal output is:

Governed Cognitive Efficiency State

Its foundational distinction is:

More Cognition ≠ Better Outcome.

2. Operational Role

The operational role of CGEM is:

to determine the minimum sufficient cognitive effort required to reliably solve the governed problem within applicable constraints.

PSEM establishes what problem should be solved.

CGEM determines how much cognitive work that problem requires.

3. Position in the COS Internal Flow

The COS internal governance flow is:

4. Central Operational Question

How much cognitive work is necessary to reliably produce the required validated outcome from the governed problem without unnecessary reasoning, inference, deliberation, or cognitive repetition?

5. Cognitive Work

Cognitive Work is the computational activity used to interpret, reason about, transform, evaluate, compare, plan, or resolve the governed problem.

It may include:

reasoning,

inference,

planning,

interpretation,

classification,

comparison,

synthesis,

evaluation,

uncertainty resolution,

or another cognitive operation.

6. Cognitive Object

Every CGEM assessment should identify the problem, task, decision, or execution state to which the cognitive work applies.

Cognitive effort should not be assessed independently from the problem it is intended to solve.

7. Cognitive Requirement

The Cognitive Requirement represents the level and type of cognitive work necessary to satisfy the Operational Requirement.

It should derive from the governed problem rather than from the maximum reasoning capability available.

Therefore:

Available Cognitive Capability ≠ Required Cognitive Effort.

8. Cognitive Necessity

A cognitive operation is necessary where removing it would materially reduce the ability of the execution to satisfy the required outcome or applicable governed constraints.

9. Cognitive Sufficiency

Cognitive Sufficiency exists where the cognitive work performed is adequate to reliably satisfy the required outcome.

Sufficiency is evaluated against the Operational Requirement.

10. Cognitive Insufficiency

Cognitive Insufficiency exists where the execution performs too little cognitive work to reliably produce the required outcome.

Possible consequences include:

incorrect reasoning,

incomplete interpretation,

missed conditions,

weak planning,

or unresolved uncertainty.

11. Cognitive Excess

Cognitive Excess exists where materially additional cognitive work is performed without sufficient improvement in the required governed outcome.

Therefore:

Additional Reasoning ≠ Additional Value by default.

12. Minimum Sufficient Cognition

Minimum Sufficient Cognition is:

the least cognitive work capable of reliably producing the required validated outcome within applicable governed constraints.

It is not the minimum amount of reasoning technically possible.

13. Cognitive Proportionality

Cognitive effort should remain proportionate to:

problem complexity,

uncertainty,

required precision,

decision difficulty,

validation requirements,

and applicable constraints.

14. Cognitive Depth

Cognitive Depth represents how extensively an execution reasons through the problem before producing an outcome.

Greater depth may be justified for difficult problems.

It should not be the universal default.

15. Shallow Cognitive Execution

Some problems require only limited interpretation or inference.

Using deep reasoning for such tasks may create unnecessary computational work.

16. Deep Cognitive Execution

Complex problems may require extended reasoning, comparison, planning, or uncertainty resolution.

Deep cognition is legitimate where the Operational Requirement supports it.

17. Adaptive Cognitive Depth

Cognitive depth may vary according to the actual problem state.

A system may use:

limited cognition for routine cases,

greater cognition for difficult cases,

and escalation for unresolved cases.

18. Uniform Cognitive Depth

Applying the same high reasoning depth to every task may create systematic computational excess.

Therefore:

Uniform Maximum Reasoning ≠ Governed Cognitive Efficiency.

19. Cognitive Escalation

Cognitive Escalation increases reasoning effort when the current cognitive state cannot reliably satisfy the required outcome.

Escalation should correspond to unresolved need.

20. Escalation Trigger

A cognitive escalation trigger may include:

unresolved ambiguity,

low confidence,

conflicting evidence,

complexity,

failed initial reasoning,

or another relevant condition.

A trigger should not automatically imply maximum reasoning.

21. Cognitive De-Escalation

Cognitive De-Escalation reduces reasoning effort where evidence demonstrates that lower cognitive effort reliably satisfies the requirement.

22. Escalation Ceiling

Where appropriate, a governed ceiling may limit cognitive escalation.

Beyond that point, another response may be more appropriate, such as:

tool use,

different model allocation,

human escalation,

or recognition that the problem remains unresolved.

23. Cognitive Saturation

Cognitive Saturation occurs where additional cognitive work produces little or no material improvement in the required outcome.

Therefore:

Reasoning Beyond Saturation ≠ Better Cognitive Performance.

24. Marginal Cognitive Benefit

CGEM may evaluate whether additional cognitive effort produces sufficient improvement in:

reliability,

completeness,

accuracy,

uncertainty resolution,

or another required property.

25. Cognitive Stopping Condition

A cognitive process should possess a condition under which sufficient reasoning has been achieved.

Without a stopping condition, reasoning may continue after the required outcome has already become sufficiently established.

26. Premature Stopping

Stopping reasoning before the required cognitive state has been reached may create insufficient execution.

Efficiency does not justify premature termination.

27. Delayed Stopping

Continuing reasoning after the required outcome has become sufficiently established may create cognitive excess.

28. Reasoning Loop

An execution may revisit the same reasoning state repeatedly.

Repeated reasoning should produce material new information or resolution to remain justified.

29. Redundant Reasoning

Redundant Reasoning occurs where cognitive work materially repeats previously completed reasoning without sufficient new operational benefit.

30. Circular Reasoning Execution

A system may repeatedly reconsider equivalent alternatives without progressing toward the required outcome.

This can create substantial computational consumption.

31. Cognitive Convergence

Cognitive Convergence occurs where further reasoning is unlikely to materially alter the required output.

Where convergence is sufficiently established, additional cognitive effort may be unnecessary.

32. Cognitive Divergence

Some reasoning processes expand into additional alternatives or interpretations.

Divergence may be legitimate during exploration but should remain proportionate to the problem.

33. Exploration Requirement

Some problems require exploration of multiple possible solutions.

The extent of exploration should correspond to the required decision quality and uncertainty.

34. Exploration Excess

Exploring alternatives that are:

irrelevant,

already excluded,

duplicated,

or materially equivalent

may create unnecessary cognitive work.

35. Candidate Reasoning

Where multiple alternatives remain feasible, cognition may compare them.

PSEM should already have reduced invalid problem-space candidates where possible.

CGEM governs the cognitive effort required among the remaining candidates.

36. Cognitive Branching

Reasoning may branch into multiple possible paths.

Branching should remain connected to legitimate unresolved alternatives.

37. Branch Pruning

Where evidence or constraints eliminate a reasoning branch, continued cognitive work on that branch may be unnecessary.

38. Cognitive Sequence

Some reasoning operations depend upon earlier cognitive states.

The sequence should avoid repeating operations whose results are already sufficiently established.

39. Cognitive Dependency

A cognitive operation may depend upon another inference, fact, interpretation, or decision.

Dependencies should remain visible where they materially affect reasoning efficiency.

40. Known-State Reuse

Previously established reliable information should be reused where appropriate rather than repeatedly reconstructed through cognition.

Therefore:

Known State ≠ New Reasoning Requirement.

41. Cognitive Reconstruction

Repeatedly deriving information already available in a sufficiently governed form may represent unnecessary cognitive work.

42. Cognitive Memory Relationship

Memory may reduce repeated cognition by preserving relevant established state.

MGIA™ governs Memory as a broader governance domain.

CGEM governs only the computational-efficiency consequence of cognitive reuse.

43. Context Requirement

Cognitive execution may require contextual information.

The required context should correspond to the governed problem.

44. Context Relevance

Only context materially relevant to the cognitive requirement should influence reasoning where practical.

Irrelevant context may increase computational work or distract reasoning.

45. Context Volume

Larger context may increase the computational burden of cognitive execution.

Therefore:

More Context ≠ More Useful Cognition by default.

46. Context Amplification

Context Amplification occurs where additional contextual material causes disproportionate growth in cognitive processing without corresponding improvement in the required outcome.

47. Context Compression

Relevant information may sometimes be represented more compactly without losing material meaning.

Where valid, compression may reduce cognitive demand.

48. Context Selection

A system may select only context relevant to the current problem state.

Context selection should preserve information necessary for reliable reasoning.

49. Context Retrieval

External retrieval may reduce the need for uncertain internal reconstruction.

However, retrieval itself creates execution and orchestration costs.

OEM subsequently governs the orchestration consequences.

50. Cognitive Uncertainty

Uncertainty may justify additional cognitive work.

The amount of additional cognition should correspond to whether further reasoning can realistically reduce that uncertainty.

51. Reducible Cognitive Uncertainty

Where additional reasoning can materially resolve uncertainty, greater cognitive effort may be justified.

52. Irreducible Cognitive Uncertainty

Where available information cannot resolve the uncertainty, additional reasoning may merely consume resources without improving the result.

Therefore:

More Reasoning ≠ More Certainty by default.

53. Uncertainty Recognition

A cognitively efficient system should be capable of recognizing when uncertainty remains unresolved rather than repeatedly reasoning toward unsupported certainty.

54. Cognitive Confidence

Where confidence measures are used, they should support rather than replace the underlying reasoning evidence.

High confidence does not independently establish cognitive sufficiency.

55. Cognitive Precision

Some tasks require high precision.

Others require only approximate or categorical outputs.

Cognitive effort should reflect the precision actually required.

56. Precision Excess

Reasoning beyond the required precision may create unnecessary cognitive consumption.

Therefore:

Maximum Precision ≠ Required Precision.

57. Cognitive Planning

Planning may be necessary where execution involves multiple dependent actions.

The depth and detail of planning should correspond to the operational requirement.

58. Planning Excess

Producing highly detailed plans for simple or reversible tasks may create unnecessary cognitive work.

59. Replanning

Replanning may be justified where material execution conditions change.

Repeated replanning without material change may represent cognitive excess.

60. Cognitive Interpretation

Unstructured or ambiguous information may require interpretation.

Where deterministic preprocessing can resolve the structure reliably, unnecessary cognitive interpretation should be avoided.

61. Cognitive Classification

Some classification tasks require little reasoning once relevant features are established.

Complex reasoning should not be introduced merely because the system supports it.

62. Cognitive Comparison

Comparative reasoning should focus on criteria relevant to the required outcome.

Unnecessary dimensions increase cognitive work without necessarily improving the decision.

63. Cognitive Synthesis

Synthesis may require combining multiple sources or states into a coherent output.

The number and depth of inputs should remain proportionate to the requirement.

64. Cognitive Verification

A reasoning process may verify its own intermediate or final output.

Verification can improve reliability but also creates additional cognition.

The verification level should correspond to the governed requirement.

65. Self-Verification

Self-verification may be useful where it materially reduces error.

Repeated self-checking without new evidence may create cognitive redundancy.

66. Independent Validation Boundary

Where independent validation is required, it should not be replaced by internal self-reasoning merely to reduce resource consumption.

VALIDOS™ governs relevant validation methodology.

67. Cognitive Correction

Where reasoning identifies an error, additional cognitive work may be required to correct it.

Correction should remain part of the complete cognitive cost.

68. Failed Reasoning

Cognitive work that fails to produce a usable outcome remains computational work.

It should not disappear from efficiency assessment because a later reasoning attempt succeeds.

69. Retry Cognition

Repeated cognitive attempts may be necessary.

However:

Successful Final Reasoning ≠ Efficient Cognitive Path.

All material retries should remain visible.

70. Cognitive Rework

Rework required because earlier cognition was insufficient should remain part of the cognitive-efficiency assessment.

71. Human Cognitive Escalation

Some unresolved problems may be more appropriately escalated to a human rather than continuing machine reasoning indefinitely.

CGEM may identify the escalation condition.

It does not determine organizational authority.

72. Tool-Assisted Cognition

Tools may reduce cognitive work by performing:

calculation,

retrieval,

search,

verification,

or specialized operations.

The tool should be used where its total execution effect is proportionate.

73. Calculation vs Reasoning

A deterministic calculation should not necessarily be reproduced through extended probabilistic reasoning.

Therefore:

Mathematical Operation ≠ Reasoning Requirement.

74. Retrieval vs Reconstruction

Where a reliable fact can be retrieved efficiently, repeatedly reconstructing it through model reasoning may be unnecessary.

75. Specialized Operation vs General Cognition

A specialized algorithm or tool may perform a narrow operation more efficiently than general reasoning.

CGEM remains mechanism-neutral.

76. Cognitive Parallelism

Multiple reasoning processes may operate in parallel.

Parallel cognition may reduce latency while increasing total computational demand.

Its use should correspond to the operational requirement.

77. Multi-Path Reasoning

Generating several independent reasoning paths may improve reliability for some problems.

It may also multiply cognitive consumption.

Therefore:

More Reasoning Paths ≠ Better Outcome by default.

78. Consensus Cognition

Multiple reasoning outputs may be combined or compared.

Consensus mechanisms should justify their additional cognitive cost.

OEM governs the surrounding orchestration.

79. Cognitive Diversity

Different reasoning approaches may be useful where the problem benefits from independent perspectives.

Diversity should not become automatic duplication.

80. Cognitive Specialization

Different cognitive functions may be separated into specialized execution components.

The resulting orchestration overhead belongs to OEM.

CGEM governs whether the cognitive functions themselves are necessary.

81. Cognitive Load

Cognitive Load represents the computational burden created by the reasoning required for the problem.

Load may vary with:

complexity,

context,

uncertainty,

depth,

branching,

and validation requirements.

82. Cognitive Load Distribution

A workflow may distribute cognitive work across:

multiple stages,

models,

agents,

or human participants.

Distribution does not eliminate cognitive consumption.

83. Cognitive Concentration

Some configurations concentrate reasoning in one high-capability execution component.

Others distribute it.

CGEM evaluates cognitive necessity rather than prescribing one architecture.

84. Cognitive Consumption

Cognitive work ultimately creates computational resource consumption.

RGS provides the resource-consumption evidence.

CGEM establishes whether the cognitive work producing that consumption is justified.

85. Cognitive Productivity Relationship

IPS governs productivity.

CGEM may use productivity evidence to determine whether additional cognitive work materially improves productive completion.

Therefore:

More Cognitive Work ≠ More Productivity by default.

86. Cognitive Value Relationship

VGS governs Value.

CGEM does not infer Value merely from cognitive complexity.

Therefore:

Complex Reasoning ≠ Valuable Reasoning.

87. Cognitive Economic Relationship

Additional cognition may create additional execution cost.

IES governs economic treatment.

CGEM governs whether the cognitive work itself is computationally necessary and proportionate.

88. Cognitive Energy Relationship

Additional cognitive computation may increase execution-related energy consumption.

CGEM may provide evidence relevant to later sustainability governance without governing the energy system itself.

89. Cognitive Constraint Relationship

Cognitive optimization must remain inside applicable governed constraints.

Reducing reasoning cannot be justified where it violates required:

validation,

safety,

reliability,

or other applicable conditions.

90. Cognitive Optimization Opportunity

A Cognitive Optimization Opportunity exists where evidence indicates that cognitive work may be reduced or restructured without compromising the required validated outcome.

91. Cognitive Optimization Hypothesis

A proposed cognitive optimization should identify:

which cognitive work will change,

why that work appears unnecessary or excessive,

what resource effect is expected,

and which outcome must remain preserved.

92. Cognitive Baseline

CGEM should establish the current cognitive execution state before optimization.

The baseline may include:

reasoning depth,

reasoning steps or stages,

context,

branching,

retries,

verification,

planning,

and relevant consumption.

93. Alternative Cognitive Configuration

Alternative configurations may vary:

reasoning depth,

context amount,

planning depth,

branching,

verification,

tool assistance,

escalation thresholds,

or stopping conditions.

94. Comparative Cognitive Assessment

Alternative cognitive configurations should be compared under sufficiently equivalent problem and outcome requirements.

A shallower reasoning path producing a weaker result is not proven more efficient.

95. Cognitive Outcome Preservation

Cognitive optimization must preserve the required validated outcome.

Therefore:

Reduced Reasoning with Reduced Sufficiency ≠ Cognitive Optimization.

96. Cognitive Regression

Reducing cognitive effort may create:

higher failure,

more retries,

greater correction,

weaker interpretation,

or unresolved uncertainty.

These effects should remain visible.

97. Cognitive Rebound

A reduction in initial reasoning may create additional cognition later through:

clarification,

retry,

validation,

correction,

or escalation.

Therefore:

Reduced Initial Cognition ≠ Reduced Total Cognition by default.

98. Cognitive Displacement

Cognitive work may be shifted to:

another model,

another agent,

a tool,

or a human.

Displacement should not be represented as elimination.

99. Cognitive Externalization

A system may appear cognitively efficient because substantial cognitive work occurs outside the measured execution boundary.

CGEM should preserve the relevant governed boundary.

100. Cognitive Evidence

Evidence may include:

reasoning traces where appropriate,

execution telemetry,

task complexity,

context size,

retry patterns,

validation results,

resource-consumption traces,

outcome quality,

or controlled comparative tests.

101. Cognitive Measurement

Possible measures may include:

reasoning duration,

reasoning stages,

context processed,

number of reasoning attempts,

branch count,

verification cycles,

or computational resources associated with cognition.

No single measure universally establishes Cognitive Efficiency.

102. Cognitive Efficiency Metric Boundary

Formal cross-system metrics belong to the VEGA™ Reference Metrics Framework.

CGEM establishes the governed states and evidence from which such metrics may be derived.

103. Cognitive Efficiency State

A cognitive execution may be represented as:

Cognitively Insufficient,

Minimum Sufficient,

Proportionate,

Cognitively Excessive,

Saturated,

Escalation Required,

Optimization Candidate,

or Unresolved.

104. Cognitive Uncertainty State

Where evidence cannot determine whether cognitive work is necessary or excessive, the state should remain unresolved.

Therefore:

Uncertain Cognitive Excess ≠ Proven Cognitive Excess.

105. Cognitive Drift

Cognitive Drift occurs where reasoning behavior changes over time without corresponding change in the Operational Requirement.

Examples may include:

increasing reasoning depth,

growing context,

additional verification,

or more retries.

106. Cognitive Reassessment

Reassessment should occur where:

the problem changes,

task complexity changes,

context changes,

failure patterns change,

model behavior changes,

validation requirements change,

or new evidence becomes available.

107. Cognitive Versioning

Material changes to cognitive configuration should be versioned where necessary for:

comparison,

traceability,

and optimization evidence.

108. Cognitive Provenance

A Governed Cognitive Efficiency State should preserve sufficient provenance to identify:

problem state,

Cognitive Requirement,

cognitive configuration,

context,

reasoning depth,

escalation conditions,

stopping conditions,

evidence,

outcome,

version,

and optimization determination.

109. Cognitive Integrity

CGEM should resist:

maximum reasoning by default,

repeated reasoning without new information,

unnecessary context processing,

reasoning toward false certainty,

excessive planning,

repeated self-verification,

ignoring failed reasoning,

hiding retries,

treating tool-capable operations as reasoning requirements,

multiplying reasoning paths without justification,

and shifting cognition outside the measurement boundary while claiming it was eliminated.

The governing principle is:

Reason only as much as the governed problem requires — and enough to satisfy it reliably.

A conforming implementation of CGEM must provide exactly the following six capabilities:

1. Cognitive Requirement & Sufficiency Governance

Capability to establish required cognitive work, sufficiency, insufficiency, proportionality, and minimum sufficient cognition.

2. Cognitive Depth, Escalation & Stopping Governance

Capability to govern adaptive reasoning depth, escalation, de-escalation, saturation, stopping conditions, and convergence.

Capability to govern context relevance, context amplification, uncertainty, planning, interpretation, comparison, synthesis, verification, and tool-assisted cognition.

118. Use Case 1 — Maximum Reasoning Applied to Routine Requests

An AI system uses extended reasoning for every incoming request, including routine tasks with well-defined inputs and outputs.

PSEM has already established that these routine cases are appropriately bounded.

CGEM evaluates the actual Cognitive Requirement and determines that many cases can reliably reach the required validated outcome with substantially lower reasoning depth.

Higher cognitive effort remains available for cases where uncertainty or complexity triggers escalation.

The system therefore stops treating maximum reasoning as the default cognitive state.

Available Cognitive Capability ≠ Required Cognitive Effort.

119. Use Case 2 — Additional Reasoning Cannot Resolve Missing Information

An intelligent system receives a case containing insufficient evidence for a reliable conclusion.

Instead of recognizing the unresolved information state, the system repeatedly reasons over the same evidence, generates alternative interpretations, and performs multiple self-verification cycles.

CGEM identifies that the remaining uncertainty is not reducible through additional cognition.

The appropriate governed state becomes unresolved or escalation-required rather than continued computational reasoning.

More Reasoning ≠ More Certainty by default.

120. Canonical Closing Statement

Cognition has a purpose.

It exists to resolve what the problem requires — not to demonstrate how much reasoning the system can perform.

Some problems need one inference.

Some need extended deliberation.

Some need tools.

Some need escalation.

And some reach a point where no amount of additional reasoning can create information that does not exist.

A cognitively efficient system therefore knows both when to think more and when further thinking has stopped producing useful resolution.

More Cognition ≠ Better Outcome.

Reason until the requirement is sufficiently resolved — not until computational capability is exhausted.

The strongest reasoning system is not the one that always thinks the longest. It is the one that can govern how much thinking the problem actually deserves.
